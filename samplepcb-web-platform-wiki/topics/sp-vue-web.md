# sp-vue-web

## Purpose [coverage: high — 16 sources]

`sp-vue` — samplepcb 신규 화면 영역의 **Vue 3 SPA** (`samplepcb-web-mono-app/apps/web`, 패키지명 `web`). 그누보드5/영카트(`sp-php`)와 **같은 도메인**에서 nginx 로 합류하며 `/app` 경로에 마운트된다(`base: '/app/'` 고정). 별칭 규칙상 "web" 호칭은 금지(PHP `samplepcb-web/` 와 혼동) — 문서·커밋에서는 `sp-vue`.

소스 날짜 범위는 2026-07-05(order-notify-gating) ~ 2026-11-06(`apps/web` 마지막 커밋은 11-05 f3b2ac129 구성도 도면·글 분리, 같은 화면이 그리는 `@sp/ui` 견적서 시트는 11-06 bc183102a, 시스템개발 범위 칩은 정본 날짜 11-06 의 미커밋 변경 — 2026-11-09 작업트리). **최근 4개월(2026-07-12~11-09)이 사실상 전부**라 "최근 합의"와 "이전 패턴"의 경계는 지난 컴파일(10-12)이다 — 이전 패턴 = 관리자 콘솔 + 고객 BOM 2축(2026-07 컴파일분, Key Decisions 하단에 날짜 그대로 보존), 07-27~09-18 의 322커밋으로 세워진 **세 번째·네 번째 축**(① 협력사 포털 `/app/partner` — BOM/PCB 모듈 분리 R1→사이드바 셸 R3→3개 언어 ② 관리자 업무 모듈 5종 — 통합·PCB·BOM·개발·마켓, 헤더 모듈 스위처 + 역할별 워크큐 + 단일 Case 상세), 09-19~10-11 51커밋의 **다섯 번째 축**: **관리자 화면을 shadcn-vue 로 다시 지은 `src/next`**(10-06~07 네 모듈)와 **10-10 컷오버**(새 화면이 정식 `/app/admin/*`, 옛 화면은 `/app/admin/legacy/*`), 그리고 고객 BOM 셸 단일 모드(09-28)·포털의 마스터딜러 화면군(10-09~11). 최근 합의 = 10-12 이후 13커밋(10-22~11-05, 전부 `feat/fix(develop)`) — 새 축이 아니라 **관리자 「개발」 모듈의 업무 확장**: 견적서 서식 재편(인건비·직접비 산출 내역·가산율·인건비 기본값·고객이 받는 1쪽 미리보기·엑셀·PDF, 11-04~06), 개별 메뉴 AI 맞춤 질문 설정 카드(10-30), 관리자 연락처 수정(11-04), 구성도 도면·글 분리(11-05). 라우트는 그대로(115 + 리다이렉트 4)이고, **컷오버 뒤 처음으로 옛 화면도 같이 고친 기간**이다 — 새 기능 화면은 새 화면에만, 금액·필드 보존과 같은 판정의 표시는 옛 화면에도(옛 화면 마크업 8파일 + 옛·새 공용 훅·순수 모듈 3). 코드 규모는 170,259줄(+1,397) — 옛 화면·포털·고객 BOM 102,786줄 + `src/next` 67,473줄(545파일, 그중 shadcn 업스트림 `components/ui` 218)(`.vue`+`.ts` 실측, 지난 판과 같은 셈법).

역할 전제는 2026-07-19 이후 "관리자 콘솔 + 일반(회원) 화면"이고(router.ts 주석 정본), 08-10 부터는 **협력사(파트너) 화면**까지 셋을 한 앱에 담는다. 셸(레이아웃)이 다섯: `DefaultLayout`(최소 홈)·**`AdminNextLayout`**(리뉴얼 관리자 셸 — 정식)·`AdminLayout`(옛 관리자 셸 — legacy 화면 + 리뉴얼하지 않은 견적관리·마켓)·`BomLayout`(Parts Eyes 고객 셸, Figma 확정 디자인)·`PartnerLayout`(옛 관리자 셸 미러). 고객 단순 화면은 여전히 sp-php(`/`), 재능마켓 소비자는 `sp-market`(`/market`), 개발의뢰 고객은 `apps/develop`(`/develop`:5177, 2026-09-05)이며 sp-vue 는 그 둘의 **관리 표면**(`/app/admin/market/*`·`/app/admin/develop/*`)을 맡는다. 관리자 콘솔은 최고관리자(cf_admin) 전용, 그누보드 `/adm` 과 병행 존속. 모노 AGENTS.md 의 "UI 프로토타입" 선언은 남아 있으나 확정 디자인이 셋으로 늘었다 — 고객 BOM 셸(07-19, 09-28 단일 모드 시안)·랜딩(08-05~18 Figma 정밀 정합)·**관리자 리뉴얼 디자인 시스템**(10-06, 정본 [ADMIN_NEXT_UI](../../docs/ADMIN_NEXT_UI.md)). 포털과 옛 셸 화면은 여전히 손으로 지은 Tailwind 다. 11-04 부터는 관리자 개발 모듈의 견적서 미리보기가 **고객이 받는 종이**(`@sp/ui DevelopQuoteSheet`, 11-06 피그마 「통합 견적서」 모양)를 그대로 띄운다 — 리뉴얼 디자인 시스템 밖의 고정 모양이다([shared-packages](shared-packages.md)).

## Architecture [coverage: high — 51 sources]

- **스택**: Vite 8 + Vue 3.5 + TypeScript 6 + Vue Router 4 + Pinia 3 + @tanstack/vue-query 5(+`vue-virtual`) + Tailwind v4 + vue-i18n 11. 인쇄·라벨용 `jspdf`·`html2canvas-pro`·`qrcode`(앞의 둘은 2026-11-05 부터 `@sp/ui` 도 같은 버전으로 의존한다). 폰트 Pretendard variable. workspace 의존 `@sp/api-contract`(Zod 계약)·`@sp/shared`(API 클라이언트·auth store·대리 접속 상태)·`@sp/utils`(bom-pricing·kst-date 등 순수 함수)·**`@sp/ui`**(검토서 뷰어·구성도·드롭존·미리보기 + 11-04~05 **개발 견적서 시트·화면 캡처 PDF·구성도 문서 파서** — 소비 앱 `style.css` 에 `@source` 필요)·`@sp/config`. **10-06 리뉴얼 묶음**: shadcn-vue(`new-york`·slate, `components.json` 직접 관리)가 끌고 온 `reka-ui`·`class-variance-authority`·`clsx`·`tailwind-merge`·`tw-animate-css`·`@lucide/vue`(아이콘)·`vue-sonner`(토스트)·`@vueuse/core`, 린터 `@shadcn/lint` 0.2.0 **고정**, tsconfig·Vite 의 `@` = `src` 별칭.
- **부트스트랩**(`main.ts`): pinia → i18n → vue-query → **마운트 전 `useAuthStore(pinia).bootstrap()`** → router 설치. 순서 필수(딥링크가 빈 auth 가드에 튕김). `App.vue` 는 `<RouterView>` + **`UiConfirmHost` 하나**(옛 화면·포털·고객 BOM 의 확인창 호스트 — 리뉴얼 셸은 자기 호스트를 따로 띄운다).
- **라우터**(`router.ts`, 641줄): `/bom`(회원, 정적 세그먼트 `search`·`history` 를 `:id` 앞에)·`/partner`(회원 가드만 프론트, 소속·승인은 서버 `requirePartner` 매 요청)·공개 3(`/rfq-reply/:token`·`/pcb-rfq-reply/:token`·`/partner-invite/:token` — 토큰이 근거)·**`/admin` 레코드 두 벌**(`requiresAdmin`): 리뉴얼 셸(`AdminNextLayout`, 셸까지 지연 로딩 — shadcn·reka-ui 묶음이 옛 번들에 섞이지 않게)과 옛 셸(`AdminLayout`)이 같은 부모 경로를 나눠 갖고 자식 경로로 갈린다. 이름 있는 라우트 115(리뉴얼 관리자 40·옛 관리자 42·옛 셸 정식 5·포털 20·고객 BOM 4·공개 3·홈 1) + 리다이렉트 4. 지연 로딩 97 — 정적 import 는 홈·BOM 4·옛 코어 관리자 12(17개) 그대로. meta 는 `requiresAdmin`·`requiresMember`·`wide`·`adminContentFlush`(BOM 워크벤치가 본문 여백 제거 — 두 셸 공통). 가드 맨 앞에서 `?actAs=<조직 id>` 를 처리한다(관리자면 `enterActAsPartner`, 주소에서 표식을 걷고 replace).
- **관리자 리뉴얼 셸**(`next/layouts/AdminNextLayout.vue`·`next/admin-menu.ts`, 정본 [ADMIN_NEXT_UI](../../docs/ADMIN_NEXT_UI.md)): 옛 셸과 **같은 배치**(좌 사이드바·상단 헤더·본문)를 shadcn Sidebar 로 — 데스크톱은 아이콘 폭으로 접히고(Ctrl/⌘+B), 768px 미만은 시트. 마운트 때 `html.sp-next` 를 붙이고 떠날 때 뗀다(전역 기본 스타일 범위). `ConfirmHost`·`PromptHost`·`Toaster` 를 하나씩 띄운다.
  - 모듈 사전 `nextModules = [core, pcb, smartbom, develop]` — 메뉴 순서·라벨 i18n 키·배지 식별자를 옛 메뉴와 같게 두고, 항목이 `{routeName, icon, to(ctx), badge?, activeRouteNames?, placement?, legacy?}` 를 든다. 모듈을 하나 더 옮길 때는 여기 항목 + 배지 훅 합산식만 더하면 사이드바·스위처·'이전 화면'이 따라온다.
  - **라우트 이름은 `NEXT_{CORE,PCB,SMARTBOM,DEVELOP}_ROUTES` 상수로만** 부른다(화면 코드에 문자열 금지). 컷오버 때 리뉴얼 화면 쪽에서 바뀐 것은 이 값과 `NEXT_*_BASE_PATH`(`admin-next-*` → `admin-*`), 라우트 레코드의 자리뿐이다 — 화면 코드는 그대로.
  - 헤더 스위처 `nextModuleLinks` 는 옛 `adminModules` 5종을 그대로 돌되 리뉴얼된 4모듈은 새 화면(PCB 는 마지막 본 워크큐)으로, **마켓은 옛 셸 홈으로** 보낸다. 통합 메뉴의 견적관리는 `legacy: true` — 옛 화면을 가리키고 이름 뒤에 '이전 화면' 아이콘이 붙는다(배지 `rfqCount` 는 유지).

- **옛 화면 정합 비용**(11-04, 개발 모듈): 새 화면에 칸이 생기면 옛 화면은 두 가지를 확인해야 한다 — (a) 옛 화면이 그 칸을 보내지 않아도 값이 지켜지는가: 설정 저장은 서버가 **보낸 칸만** 고쳐 옛 설정 화면에서 저장해도 가산율·인건비 기본값이 남고, 옛 편집기는 공용 `develop-quote-edit.ts` 가 받은 새 칸(구분·등급·수량·단위·가산율)을 그대로 돌려보낸다 (b) 그 칸이 바꾼 금액·판정이 옛 화면에 보이는가: 가산 줄이 없어 '합계가 왜 늘었나'가 안 보이던 것을 리뷰가 지적해서야 읽기 전용 줄을 넣었다(9fc21f8eb). e2e `admin-develop-journey` 는 `DEVELOP_ADMIN_UI=old|next` 로 같은 스펙을 두 번 돌리되 새 화면 전용 단계(8 설정 인건비 기본값·9 연락처 수정)는 옛 모드에서 `return` 한다 — 옛 모드의 green 은 그 단계를 검증하지 않은 green 이다([parallel-build-cutover](../concepts/parallel-build-cutover.md)).
- **견적서 종이는 `@sp/ui` 안에 있다**(11-04~): `DevelopQuoteSheet` 는 scoped CSS 고정 색·A4 폭(210mm)이라 리뉴얼 토큰(`theme.css`)·다크 테마와 무관한 흰 종이고, `src/next` 린트·`next-ui-audit` 는 패키지 안을 보지 않는다 — 종이 서식을 `src/next/**/print/` 가 아니라 `@sp/ui` 에 둔 첫 사례(고객 앱과 같은 종이여야 해서). 미리보기 대화상자는 `overflow-x-auto` 로 폭을 줄이지 않는다. PDF 는 그 종이의 화면 캡처라 글자가 그림이다(선택·검색 불가 — 고를 수 있는 파일은 엑셀·브라우저 인쇄), 글자 간격·숫자 폭 함정은 [shared-packages](shared-packages.md).
- **같은 견적의 '수신'이 문서마다 다를 수 있다**(11-04~): 견적서 미리보기·인쇄·엑셀은 **지금 연락처**를 그려 관리자가 연락처를 고치면 이미 보낸 견적의 수신 칸도 바뀌고, 보낸 메일 본문·영카트 주문은 그때 값 그대로다. 계약 근거는 따로 박제된 수락 기록(수락자·시각)이다.
- **견적 편집기 줄 모양은 창 폭이 아니라 칸 폭으로 정해진다**: `QuoteItemsField` 의 container query(56rem) 때문에 같은 창에서도 사이드바 접힘·'의뢰 내용 옆 보기'(우측 420px) 여부에 따라 한 줄 표와 두 줄 모양이 갈릴 수 있다 — 캡처·e2e 에서 모양이 창 크기만으로 정해지지 않는다(정본 [DEVELOP_FLOW](../../docs/DEVELOP_FLOW.md) §5.1 '편집기').
- **AI 설정 안내문이 낡았다**(11-02~): 맞춤 질문 카드의 `enabledHint`(ko·en)가 'PCB' 를 AI 가 처리하는 메뉴로 적지만, 11-02 부터 PCB 설계는 고정 질문이다(`DEVELOP_AREA_FOLLOWUP_FIXED_AREAS = ['pcb']` — PCB 만이면 실행 라우트 400 `AREA_REQUIRED`). 동작이 아니라 화면 문구만 낡았다.
- **`src/next` 규율**: `<style>` 블록·인라인 style·임의값(배치 외)·Tailwind 기본 팔레트·옛 토큰(`ink-*`·`surface-*`·`brand-*`) 금지, 옛 `@/components/**` import 금지(예외: 인쇄 문서 `EstimateSheet`·`usePrintIsolation`, `@sp/ui` 고객 공용 문서 뷰). **옛 `@/lib/confirmDialog` 를 부르면 옛 모양 창이 뜬다** — `@/next/lib/dialog`. 고친 뒤 `npx eslint <고친 파일>` + `node scripts/next-ui-audit.mjs`(전체 eslint 는 타입 인지라 수 분). 린터가 못 보는 곳(`<style>`·부모 선택자·import 한 class 값·`<component :is>`)이 있어 통과가 곧 일관성은 아니다.
- **shadcn 생성 코드 함정**: `shadcn-vue init` 금지(전역 base 레이어·radius 를 CSS 에 써넣는다), `add --overwrite` 는 관리자 밀도(32px)로 고친 높이를 되돌린다(button·input·select·tabs 등). `exactOptionalPropertyTypes` 와 reka-ui prop 타입이 파일마다 한 줄씩 충돌 — `scripts/next-ui-expect-errors.mjs` 가 사유 주석을 단다. `@shadcn/lint` 는 0.2.0 고정.
- **리뉴얼 e2e 선택자**: 탭이 `role=tab`, 체크박스가 `button role=checkbox`(`input[type=checkbox].check()` 불가), 대화상자가 body 포털(`getByRole('dialog'|'alertdialog')`), 사이드바는 `[data-sidebar=sidebar]`, 설정 켜기/끄기는 `role=switch`. `/app/admin/{pcb,smartbom,bom,develop,…}` 를 옛 선택자로 보던 스펙은 이제 새 화면을 연다 — 맞추거나 `/app/admin/legacy/…` 로 옮길 것(미완, [testing](testing.md)).
- **종이에 남는 주소는 정식 경로**: 라벨 QR 은 `/app/admin/pcb/packages/…` 를 찍는다 — 리뉴얼 중에도 `next` 경로를 찍지 않았던 이유(컷오버 뒤 죽은 링크).
- **대리 접속은 탭 단위**: `sp.actAsPartner` 가 sessionStorage 라 [포털로 보기]가 연 탭에서만 유효하고, `usePartnerAccess` 키에 조직 id 가 들어가 내 판정과 캐시가 섞이지 않는다. 나갈 때 SPA 이동이 아니라 전체 새로 읽기인 것도 같은 이유(포털 조회 캐시에 그 조직 데이터가 남는다).
- **BOM 셸 테마 고정의 두 곳 동기**: `index.html` 부팅 스크립트와 `BomLayout` 의 `pinTheme` 이 같은 규칙이어야 한다(다르면 마운트 전 한 번 어둡게 깜빡임). `useTheme` 초기값은 **문서 속성이 아니라 저장값·OS** 에서 읽는다 — 속성을 읽으면 BOM 진입 후 관리자로 갈 때 다크가 돌아오지 않았다. 어두운 패널 안의 모달은 body 로 Teleport 해야 밝게 뜬다(`BomClaimPanel`).
- **`type=number` 의 `v-model` 은 숫자를 준다**(비우면 빈 문자열) — 문자열로 가정하고 `trim` 하면 입력한 순간 터져 저장이 조용히 안 된다(`useBomPartnerFxEditor`·`useBomRemittanceEditor` 가 어느 쪽이 와도 문자열로 읽는 이유).
- **역할 서술 문서 불일치(지속)**: 루트 AGENTS.md 표·본문은 아직 "sp-vue = 관리자 전용", 모노 AGENTS.md 도 "실질 기본 용도는 관리자"(포털 i18n 예외·관리자 리뉴얼 줄만 추가). 정본은 router.ts 주석 + PARTNER_PORTAL.md — 셋(관리자·회원·협력사)을 담는다. ADMIN_NEXT_UI 는 §0(컷오버)이 정본이고 §1·§10~12 의 `/app/admin/next/*`·`admin-next-*` 표기는 컷오버 전 서술이다.
- **워크큐 기본 탭이 "우리 건"의 탭이 아니다**: PCB 진행현황 기본=발주·생산, 발주 워크큐=발주 대기, 주문·결제=입금 대기, 포털은 `todo`. 검증·탐색 시 탭 클릭+검색으로 좁힐 것 — e2e 오탐의 단골.

- **포털 사이드바 라벨은 `partner.menu.*` i18n 키가 아니라 `PartnerLayout` 안 `MENU_LABELS` 사전**(09-06 개선안 문구 — '발주 관리'·'선적 관리', 10-11 전에는 '출하 준비')을 `pt()` 로 번역한다. `labelKey` 는 식별자 역할만. 메뉴 문구를 바꾸려면 두 곳을 보되 실제 표시는 사전 쪽.
- **`pt()` 는 원문 키 정확 일치** — 원문 한 글자가 바뀌면 조용히 번역이 빠진다. e2e `partner-i18n` 스펙이 누락·변수 불일치·중복 키를 검사하므로 문구 수정 후 반드시 돌릴 것.

# sp-vue-web

## Purpose [coverage: high — 14 sources]

`sp-vue` — samplepcb 신규 화면 영역의 **Vue 3 SPA** (`samplepcb-web-mono-app/apps/web`, 패키지명 `web`). 그누보드5/영카트(`sp-php`)와 **같은 도메인**에서 nginx 로 합류하며 `/app` 경로에 마운트된다(`base: '/app/'` 고정). 별칭 규칙상 "web" 호칭은 금지(PHP `samplepcb-web/` 와 혼동) — 문서·커밋에서는 `sp-vue`.

소스 날짜 범위는 2026-07-05(order-notify-gating) ~ 2026-10-11(PARTNER_PORTAL 어휘 통일·마지막 커밋 d9683ae01). **최근 3개월(2026-07-12~10-12)이 사실상 전부**라 "최근 합의"와 "이전 패턴"의 경계는 지난 컴파일(09-19)이다 — 이전 패턴 = 관리자 콘솔 + 고객 BOM 2축(2026-07 컴파일분, Key Decisions 하단에 날짜 그대로 보존)과 07-27~09-18 의 322커밋으로 세워진 **세 번째·네 번째 축**(① 협력사 포털 `/app/partner` — BOM/PCB 모듈 분리 R1→사이드바 셸 R3→3개 언어 ② 관리자 업무 모듈 5종 — 통합·PCB·BOM·개발·마켓, 헤더 모듈 스위처 + 역할별 워크큐 + 단일 Case 상세). 최근 합의 = 09-19 이후 51커밋(9월 3·10월 48)의 **다섯 번째 축**: **관리자 화면을 shadcn-vue 로 다시 지은 `src/next`**(10-06~07 네 모듈)와 **10-10 컷오버**(새 화면이 정식 `/app/admin/*`, 옛 화면은 `/app/admin/legacy/*`), 그리고 고객 BOM 셸 단일 모드(09-28)·포털의 마스터딜러 화면군(10-09~11). 코드 규모는 168,862줄 — 옛 화면·포털·고객 BOM 102,274줄 + `src/next` 66,588줄(543파일, 그중 shadcn 업스트림 `components/ui` 218).

역할 전제는 2026-07-19 이후 "관리자 콘솔 + 일반(회원) 화면"이고(router.ts 주석 정본), 08-10 부터는 **협력사(파트너) 화면**까지 셋을 한 앱에 담는다. 셸(레이아웃)이 다섯: `DefaultLayout`(최소 홈)·**`AdminNextLayout`**(리뉴얼 관리자 셸 — 정식)·`AdminLayout`(옛 관리자 셸 — legacy 화면 + 리뉴얼하지 않은 견적관리·마켓)·`BomLayout`(Parts Eyes 고객 셸, Figma 확정 디자인)·`PartnerLayout`(옛 관리자 셸 미러). 고객 단순 화면은 여전히 sp-php(`/`), 재능마켓 소비자는 `sp-market`(`/market`), 개발의뢰 고객은 `apps/develop`(`/develop`:5177, 2026-09-05)이며 sp-vue 는 그 둘의 **관리 표면**(`/app/admin/market/*`·`/app/admin/develop/*`)을 맡는다. 관리자 콘솔은 최고관리자(cf_admin) 전용, 그누보드 `/adm` 과 병행 존속. 모노 AGENTS.md 의 "UI 프로토타입" 선언은 남아 있으나 확정 디자인이 셋으로 늘었다 — 고객 BOM 셸(07-19, 09-28 단일 모드 시안)·랜딩(08-05~18 Figma 정밀 정합)·**관리자 리뉴얼 디자인 시스템**(10-06, 정본 [ADMIN_NEXT_UI](../../docs/ADMIN_NEXT_UI.md)). 포털과 옛 셸 화면은 여전히 손으로 지은 Tailwind 다.

## Architecture [coverage: high — 39 sources]

- **스택**: Vite 8 + Vue 3.5 + TypeScript 6 + Vue Router 4 + Pinia 3 + @tanstack/vue-query 5(+`vue-virtual`) + Tailwind v4 + vue-i18n 11. 인쇄·라벨용 `jspdf`·`html2canvas-pro`·`qrcode`. 폰트 Pretendard variable. workspace 의존 `@sp/api-contract`(Zod 계약)·`@sp/shared`(API 클라이언트·auth store·대리 접속 상태)·`@sp/utils`(bom-pricing·kst-date 등 순수 함수)·**`@sp/ui`**(검토서 뷰어·구성도·드롭존·미리보기 — 소비 앱 `style.css` 에 `@source` 필요)·`@sp/config`. **10-06 리뉴얼 묶음**: shadcn-vue(`new-york`·slate, `components.json` 직접 관리)가 끌고 온 `reka-ui`·`class-variance-authority`·`clsx`·`tailwind-merge`·`tw-animate-css`·`@lucide/vue`(아이콘)·`vue-sonner`(토스트)·`@vueuse/core`, 린터 `@shadcn/lint` 0.2.0 **고정**, tsconfig·Vite 의 `@` = `src` 별칭.
- **부트스트랩**(`main.ts`): pinia → i18n → vue-query → **마운트 전 `useAuthStore(pinia).bootstrap()`** → router 설치. 순서 필수(딥링크가 빈 auth 가드에 튕김). `App.vue` 는 `<RouterView>` + **`UiConfirmHost` 하나**(옛 화면·포털·고객 BOM 의 확인창 호스트 — 리뉴얼 셸은 자기 호스트를 따로 띄운다).
- **라우터**(`router.ts`, 641줄): `/bom`(회원, 정적 세그먼트 `search`·`history` 를 `:id` 앞에)·`/partner`(회원 가드만 프론트, 소속·승인은 서버 `requirePartner` 매 요청)·공개 3(`/rfq-reply/:token`·`/pcb-rfq-reply/:token`·`/partner-invite/:token` — 토큰이 근거)·**`/admin` 레코드 두 벌**(`requiresAdmin`): 리뉴얼 셸(`AdminNextLayout`, 셸까지 지연 로딩 — shadcn·reka-ui 묶음이 옛 번들에 섞이지 않게)과 옛 셸(`AdminLayout`)이 같은 부모 경로를 나눠 갖고 자식 경로로 갈린다. 이름 있는 라우트 115(리뉴얼 관리자 40·옛 관리자 42·옛 셸 정식 5·포털 20·고객 BOM 4·공개 3·홈 1) + 리다이렉트 4. 지연 로딩 97 — 정적 import 는 홈·BOM 4·옛 코어 관리자 12(17개) 그대로. meta 는 `requiresAdmin`·`requiresMember`·`wide`·`adminContentFlush`(BOM 워크벤치가 본문 여백 제거 — 두 셸 공통). 가드 맨 앞에서 `?actAs=<조직 id>` 를 처리한다(관리자면 `enterActAsPartner`, 주소에서 표식을 걷고 replace).
- **관리자 리뉴얼 셸**(`next/layouts/AdminNextLayout.vue`·`next/admin-menu.ts`, 정본 [ADMIN_NEXT_UI](../../docs/ADMIN_NEXT_UI.md)): 옛 셸과 **같은 배치**(좌 사이드바·상단 헤더·본문)를 shadcn Sidebar 로 — 데스크톱은 아이콘 폭으로 접히고(Ctrl/⌘+B), 768px 미만은 시트. 마운트 때 `html.sp-next` 를 붙이고 떠날 때 뗀다(전역 기본 스타일 범위). `ConfirmHost`·`PromptHost`·`Toaster` 를 하나씩 띄운다.

- **BOM 셸 테마 고정의 두 곳 동기**: `index.html` 부팅 스크립트와 `BomLayout` 의 `pinTheme` 이 같은 규칙이어야 한다(다르면 마운트 전 한 번 어둡게 깜빡임). `useTheme` 초기값은 **문서 속성이 아니라 저장값·OS** 에서 읽는다 — 속성을 읽으면 BOM 진입 후 관리자로 갈 때 다크가 돌아오지 않았다. 어두운 패널 안의 모달은 body 로 Teleport 해야 밝게 뜬다(`BomClaimPanel`).
- **`type=number` 의 `v-model` 은 숫자를 준다**(비우면 빈 문자열) — 문자열로 가정하고 `trim` 하면 입력한 순간 터져 저장이 조용히 안 된다(`useBomPartnerFxEditor`·`useBomRemittanceEditor` 가 어느 쪽이 와도 문자열로 읽는 이유).
- **역할 서술 문서 불일치(지속)**: 루트 AGENTS.md 표·본문은 아직 "sp-vue = 관리자 전용", 모노 AGENTS.md 도 "실질 기본 용도는 관리자"(포털 i18n 예외·관리자 리뉴얼 줄만 추가). 정본은 router.ts 주석 + PARTNER_PORTAL.md — 셋(관리자·회원·협력사)을 담는다. ADMIN_NEXT_UI 는 §0(컷오버)이 정본이고 §1·§10~12 의 `/app/admin/next/*`·`admin-next-*` 표기는 컷오버 전 서술이다.
- **워크큐 기본 탭이 "우리 건"의 탭이 아니다**: PCB 진행현황 기본=발주·생산, 발주 워크큐=발주 대기, 주문·결제=입금 대기, 포털은 `todo`. 검증·탐색 시 탭 클릭+검색으로 좁힐 것 — e2e 오탐의 단골.

- **포털 사이드바 라벨은 `partner.menu.*` i18n 키가 아니라 `PartnerLayout` 안 `MENU_LABELS` 사전**(09-06 개선안 문구 — '발주 관리'·'선적 관리', 10-11 전에는 '출하 준비')을 `pt()` 로 번역한다. `labelKey` 는 식별자 역할만. 메뉴 문구를 바꾸려면 두 곳을 보되 실제 표시는 사전 쪽.
- **`pt()` 는 원문 키 정확 일치** — 원문 한 글자가 바뀌면 조용히 번역이 빠진다. e2e `partner-i18n` 스펙이 누락·변수 불일치·중복 키를 검사하므로 문구 수정 후 반드시 돌릴 것.
- **엔진 판정을 FE 가 재구성하지 말 것**(지속): 재고 사유·`quantityState`·`searchMatch`·EQ 반려·myTurn·step 전부 서버 필드. "금액 없음 ≠ 미선정".

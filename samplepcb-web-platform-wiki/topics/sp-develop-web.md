# sp-develop-web

## Purpose [coverage: high — 13 sources]

`sp-develop` — **개발의뢰(의뢰자 ↔ 샘플피씨비 직접 개발 용역) 고객 대면 Vue 3 SPA** (`samplepcb-web-mono-app/apps/develop`, base `/develop/`, 포트 **5177**) + 그 백엔드(`apps/api/src/routes/develop-requests.ts`·`admin-develop-*.ts`) + 관리자 「개발」 모듈(sp-vue `/app/admin/develop/*`). 소스 날짜 범위는 **2026-08-28(AI 사전 검토서 1건 체계) ~ 2026-11-13(확인 사항 고객 답변 §7.2.13)**. 2026-10-12 판까지는 고객 앱(`apps/develop`)의 코드 최종 커밋이 2026-09-11(간편 서식 간소화·운영 G 정리)에 멈춰 있었고 그 뒤의 변화는 셋이었다 — 관리자 「개발」 모듈의 **shadcn 리뉴얼(2026-10-07)과 정식 경로 컷오버(2026-10-10)**, 그 과정에서 나온 **프로세스 검토 23건(§15, 미결)**, 증빙 IP 기록 교정(2026-10-05). → **2026-10-22~11-06 고객 앱이 피그마 「개발 의뢰」 시안(메인 사이트와 다른 파일 `U7VKC9FSkojpDXqZ5qnJQN`)대로 전면 재편됐다**(그 기간 커밋 60건 중 `(develop)` 52건, `apps/develop` 145경로): 화면 재편과 **어두운 앱 셸**, 의뢰 **출력물**, **메뉴 6장·분야 7종(역설계 신설)**, **개별 메뉴 AI 맞춤 질문(시험 운영)**, PCB 설계 전용 2·4스텝, 견적서 **산출 내역 서식**(인쇄·엑셀·PDF), 관리자 연락처 수정(Key Decisions 5~16). → **2026-11-12~13 3막**(기간 커밋 17건 중 `(develop)` 10건, 전부 푸시됨 — 지난 판의 '미커밋'은 11-12 커밋으로 해소): ① 시스템개발 범위 질문(11-06 결정분 커밋) ② **의뢰 출력물을 16:9 장(슬라이드) 판으로** — 4:3 쪽 나눔·크기 규칙을 버리고 `DeckBook` 하나가 장을 계획 ③ **의뢰 상세도 같은 장으로** — 읽는 탭 셋·견적서는 넘겨 보는 장, 진행·문의·첨부·문서 목록은 장 모양의 판(피그마 00-3 탭 본문 모양에서 벗어남, 옛 탭 본문·전용 검토서 뷰 `DevelopReview` 삭제) ④ **확인이 필요한 사항에 고객이 직접 답한다** — 저장 = `question_answered` 이벤트, DB 변경 없음(Key Decisions 1~4). §15 23건은 그대로 미결이다. 정본은 [DEVELOP_FLOW](../../docs/DEVELOP_FLOW.md)(§5.1 견적서 서식·§7.2.3~7.2.13 위저드·출력물·상세 재편이 최신 합의, §12 의 4:3 출력물 결정 로그는 §7.2.10 으로 대체, 화면과 시안의 편차·결정은 [FIGMA_PAGES](../../docs/FIGMA_PAGES.md) 개발의뢰 4절) — 2026-09-05 의 3스텝 위저드·2026-09-09 의 문서 8종·G/C 공존(09-09~10)·2026-09-08 의 "개별 메뉴 = PCB·기구·앱·서버(회로·펌웨어는 시스템개발 안에서만)"·견적 항목 = 이름+금액 한 줄(붙여넣기 파싱)·10-22~11-06 의 4:3 쪽 나눔 출력물·시안 탭 본문 카드는 **이전 패턴**이고, 지금은 **5스텝 위저드(메뉴 6장 — 메뉴에 따라 스텝 생략·PCB 전용 모양)·문서 5종·C 단독 정본·산출 내역 견적서·16:9 장으로 읽는 출력물과 상세**다. 공개 도메인은 **centrafab.co.kr**(samplepcb.co.kr 은 다른 호스팅).

**왜 만들었나**: 재능마켓([sp-market-web](sp-market-web.md))은 전문가 매칭 구조라, 성숙 전에 상담·견적·진행·납품 노하우를 **당사가 직접 수행하는 과도적 사이트**에서 먼저 쌓는다. 레거시 `shop/estimate.php?category=circuit` "개발의뢰"(→`sp_estimate`→관리자 항목 견적→ca_id 20 카트)의 현대판이며, DB 이관에서 빠져 플랫폼에 대응물이 없던 트랙이다. 마켓과의 결정적 차이 셋: **전문가·입찰·공개 목록이 없다**(전부 소유자·관리자만) · **AI 는 고객이 아니라 관리자가 돌린다**(초안→편집→공개) · **견적은 당사가 항목별로 낸다**(마일스톤 결제). "고객 대면 신규 화면 = sp-php" 원칙의 두 번째 예외(첫째는 마켓)로, 루트 [AGENTS.md](../../AGENTS.md) 호칭 표에 `sp-develop` 이 추가됐고 `/develop` 은 그누보드 예약 경로다.

흐름(정본 §4): `received → reviewing → quoted → accepted → in_progress → delivered → completed` (+`cancelled`·`declined`). 접수 즉시 서버가 **AI 사전 검토서·시스템 구성도 초안을 백그라운드로** 만들고(관리자 전용), 관리자가 편집·공개(2026-11-13 부터 고객은 공개본의 '확인이 필요한 사항'에 직접 답할 수 있다 — 선택, 수락을 막지 않음) → 산출 내역 견적서(인건비·직접비 + 가산 3행, 2026-11-04 — 그 전엔 항목별 금액 한 줄) 발송 → 고객 수락(조건 동의 = 계약) → 마일스톤별 영카트 결제(lazy paid 승격) → 착수 뒤 **프로젝트 문서 5종·업무표**(§13) → 납품·검수(7일 자동확정) → 잔금 후 최종 산출물 잠금 해제.

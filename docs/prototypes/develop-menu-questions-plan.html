세부 질문 변경 검토 요청

의뢰서 1단계 '개발 메뉴'를 새 디자인대로 6개로 바꿉니다. 메뉴가 바뀌면 3단계 '세부 질문'도 함께 바뀌어야 합니다. 새로 생기는 회로 설계·펌웨어 개발·역설계 메뉴의 질문은 디자인에 없어서 저희가 초안을 만들었습니다. 고객 입장에서 읽어 보시고 괜찮은지, 고칠 곳이 있는지 알려 주세요.

그대로인 것

  • 세부 질문은 모두 건너뛸 수 있습니다. 예외는 역설계 '권리 확인' 1개입니다.
  • 선택형 질문에는 늘 '잘 모르겠어요'나 '전문가 추천' 같은 선택지가 있어, 몰라도 답할 수 있습니다.
  • 화면 모양(왼쪽 목차, 접었다 펴는 질문 묶음, 선택 칩)은 지금 01-3 디자인 그대로입니다.
  • 시스템 개발 방식과 PCB·앱·서버 질문은 바뀌지 않습니다. 지금 질문은 아래에서 펼쳐 볼 수 있습니다.
시스템 개발 질문 (지금 그대로)

AI가 자료를 읽고 질문을 고릅니다(최대 8개). AI를 쓸 수 없을 때는 아래 기본 3문항을 묻습니다.

  1. 제품은 누가, 어디에서, 어떻게 사용하나요?
  2. 어떤 정보를 받아서 무엇을 움직이거나 알려줘야 하나요?
  3. 고장이나 통신 중단 시 제품은 어떻게 동작해야 하나요?

늘 묻는 2문항

  1. 제품 외관 디자인은 어떻게 준비하시나요?
  2. 기구설계는 어떻게 준비하시나요?
PCB 설계 질문 7개 (지금 그대로)
  1. 신규 설계인가요, 기존 PCB 수정·재설계인가요?
  2. 희망하는 PCB 설계툴과 버전을 알려주세요.
  3. PCB 설계에 사용할 회로·기판 자료는 어떤 형태인가요?
  4. PCB 종류, 레이어, 외형과 두께를 알려주세요.
  5. 고정홀, 커넥터, 스위치와 기구 간섭 조건을 알려주세요.
  6. 주의가 필요한 신호와 배선 조건이 있나요?
  7. 원하는 PCB 설계 납품 결과물을 알려주세요.
앱 개발 질문 6개 (지금 그대로)
  1. 사용 기기와 지원 언어·국가를 알려주세요.
  2. 필수 기능과 사용 순서를 알려주세요.
  3. 사용자 역할과 권한을 알려주세요.
  4. 제품·서버 연결방식과 사용 범위를 알려주세요.
  5. 연결이 끊겼을 때 필요한 기능과 복구 동작을 알려주세요.
  6. 배포와 납품 결과물을 알려주세요.
서버 개발 질문 6개 (지금 그대로)
  1. 신규 서버인가요, 기존 시스템 개선·이전인가요?
  2. 연결 대상과 초기·향후 사용 규모를 알려주세요.
  3. 서버와 관리자 화면의 주요 업무를 알려주세요.
  4. 통신 프로토콜과 API 명세 상태를 알려주세요.
  5. 설치환경과 보안·백업·복구 요구사항을 알려주세요.
  6. 필요한 납품 결과물을 알려주세요.
기구 설계 질문 7개 (메뉴와 함께 빠짐)
  1. 신규 기구설계인가요, 기존 제품 수정·복원인가요?
  2. 목표 외형 크기와 무게 제한을 알려주세요.
  3. 내부 구성품과 고정된 위치를 알려주세요.
  4. 재질과 제작 방식을 알려주세요.
  5. 사용환경과 보호 조건을 알려주세요.
  6. 발열원과 냉각 방식에 제한이 있나요?
  7. 필요한 기구설계 결과물을 알려주세요.

새 질문 초안

고객에게 보이는 질문 문구와 선택지, 그리고 그 질문이 왜 필요한지 적었습니다. 의견은 번호로 짚어 주시면 됩니다(예: 회로 설계 3번). 질문 수는 지금 PCB 설계와 같게 메뉴마다 7개로 맞췄습니다.

여러 메뉴를 고를 때

고른 메뉴마다 질문 묶음이 하나씩 붙어서, 여러 개를 고르면 질문이 길어집니다.

시스템 개발최대 10 (AI 질문 8 + 늘 묻는 2)
메뉴 1개7
앱 및 서버 개발7 (앱만·서버만) / 13 (둘 다)
회로 + 펌웨어 (디자인 예시)14

그래서 넣을 안내

  • 메뉴를 3개 이상 고르면 1단계 카드 아래에 "여러 분야를 함께 개발하시면 시스템 개발(통합)이 질문 대신 자료를 읽고 필요한 것만 묻습니다"라고 안내합니다. 막지는 않습니다.
  • 펌웨어에서 '하드웨어부터 필요'를 고르면 "1단계에서 회로 설계·PCB 설계를 함께 고르시면 같이 견적합니다"라고 안내합니다.
  • 역설계에서 '새로 작성 필요'(펌웨어)를 고르면 펌웨어 개발을 함께 고르도록 같은 방식으로 안내합니다.
  • 회로 설계와 PCB 설계를 함께 골라도 설계 프로그램은 PCB 쪽에서 한 번만 묻습니다.

확인 부탁드리는 것

1

새로 만든 질문 21개, 이대로 써도 될까요?

제안회로 설계·펌웨어 개발·역설계 메뉴는 디자인에 질문이 없어서, 저희가 메뉴마다 7개씩 모두 21개를 새로 만들었습니다. 위 새 질문 초안에 고객이 보게 될 모양 그대로 있습니다.

여쭤볼 것이 질문들을 이대로 써도 될까요?

2

역설계 '권리 확인' 질문과 안내 문구

제안역설계 묶음 맨 위에 "권리자 허락 없이 타사 제품을 복제하는 의뢰는 받지 않습니다. 잠긴 칩의 프로그램은 추출하지 않습니다."를 적고, 권리 확인 질문은 꼭 답해야 접수되게 합니다. '단종품 유지보수 목적'이나 '확인이 필요함'을 고르면 담당자가 견적 전에 고객에게 확인합니다.

여쭤볼 것이 기준과 안내 문구로 역설계를 받아도 될까요?

3

기구 설계 메뉴가 빠지는 것

제안새 디자인대로 뺍니다. 기구가 필요한 고객은 시스템 개발로 의뢰하고, 기구만 따로 하는 견적은 받지 않게 됩니다. 기구 7문항(크기·재질·방열 등)도 더 이상 묻지 않습니다.

여쭤볼 것기구 설계 메뉴를 빼도 될까요?

4

'앱 및 서버 개발'의 범위 질문

제안카드를 누르면 '앱과 서버 모두'로 시작하고, 3단계 첫 질문에서 '앱만'이나 '서버만'으로 줄일 수 있게 합니다. 1단계 카드는 디자인 그대로 한 번 누르는 카드입니다.

여쭤볼 것범위를 3단계 첫 질문에서 묻는 방식으로 해도 될까요?

5

여러 메뉴를 고를 때 질문 수

제안질문 수는 줄이지 않고, 3개 이상 고르면 시스템 개발을 권하는 안내만 띄웁니다. 질문은 모두 건너뛸 수 있습니다.

여쭤볼 것질문 수는 그대로 두고 안내만 띄워도 될까요?

6

역설계 샘플과 견적 순서운영

제안접수 때는 사진과 자료로 대략적인 범위만 보고, 실물 샘플을 받은 뒤 견적을 확정합니다. 샘플은 고객이 보내고, 돌려받는 택배비는 고객 부담으로 안내합니다. 분해(파괴) 분석에 동의한 샘플은 돌려드리지 못할 수 있다고 3단계 샘플 질문 옆에 미리 적습니다.

여쭤볼 것이 순서와 비용 기준으로 해도 될까요?

7

메뉴에 맞지 않는 다른 단계 질문

제안4단계 '제작 계획'(시제품 수량·PCB 제작·조립)은 펌웨어 개발이나 앱 및 서버 개발만 고른 의뢰에서는 건너뜁니다. 만들 하드웨어가 없기 때문입니다. 회로·PCB·역설계·시스템 개발이 하나라도 있으면 지금처럼 묻습니다. 2단계 '지금 단계 → 목표 단계'(아이디어 … 양산 준비)는 역설계만 고른 의뢰에서 숨깁니다. 이미 실물이 있어 맞는 선택지가 없습니다.

여쭤볼 것두 질문을 이렇게 건너뛰어도 될까요?

8

단계 검토 문서에 '역설계' 단계 추가

제안계약 뒤 고객이 승인하는 단계 검토 문서는 단계 8개(요구사항·시스템 구성, 회로설계, PCB 부품배치·배선, 펌웨어·앱·서버, 기구설계, PCB·부품 제작, SMT·조립, 시험·인증) 중에서 고릅니다. 역설계에 맞는 단계가 없어 '역설계 분석(분해·회로 추적)'을 하나 더합니다. '기구설계' 단계는 시스템 개발에서 계속 쓰므로 남깁니다.

여쭤볼 것'역설계 분석(분해·회로 추적)' 단계를 이 이름으로 더해도 될까요?

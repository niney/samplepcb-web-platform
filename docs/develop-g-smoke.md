# 개발(G) 단계별 보존 스모크

접수부터 잔금 완료까지 실제 로컬 API로 진행하고, 각 단계에 멈춘 의뢰를 별도로 남긴다. 관리자·전용 고객 계정으로 화면을 확인하고 단계별 API 상태, 결과, 스크린샷을 함께 보관한다. G/C 공존 브랜치에서도 C 의뢰를 사용하지 않는다.

## 실행과 확인

평소처럼 로컬 `pnpm dev`가 실행된 상태에서 모노레포 디렉터리에서 실행한다. 기존 API `.env`를 사용하며 별도 기능용 환경변수는 없다.

```sh
pnpm --filter api develop:g-smoke run
```

실행 결과에 보고서 경로와 실행 번호가 출력된다. 보고서에서 각 의뢰의 관리자·고객 링크와 스크린샷을 열 수 있다. 관리자 링크는 기존 관리자 로그인으로 사용한다. 고객은 `.tmp/develop-g-smoke/credentials.json`의 전용 계정으로 로그인한다. 비밀번호·토큰은 보고서 본문이나 Git에 넣지 않는다.

관리자와 고객은 별도 브라우저나 시크릿 창을 사용하면 서로의 로그인 세션을 바꾸지 않고 비교할 수 있다. `capture`는 현재 화면을 다시 저장하며, 최초 기준 상태와 달라졌는지는 `status`로 확인한다.

| 단계 | 남기는 상태 |
|---|---|
| 01 | 접수 |
| 02 | 검토서 공개 — 수동 작성 시험 자료, 실제 LLM 호출 없음 |
| 03 | 견적 발송 |
| 04 | 견적 수락·착수금 대기 |
| 05 | 착수금 확인·필수자료 대기 |
| 06 | 자료 확인·착수 준비 완료 |
| 07 | 개발 진행·일정 공개 |
| 08 | 중간 검토서 공개·고객 승인 대기·후속 작업 제한 |
| 09 | 고객 수정 요청 |
| 10 | 수정본 v2 승인·작업 진행·수동 중도금 청구/확인 |
| 11 | 납품·검수 대기·파일 잠금 |
| 12 | 검수 완료·잔금 대기·파일 잠금 유지 |
| 13 | 잔금 확인·파일 다운로드 해제 |

의뢰 제목은 `[G-TEST:<실행번호>] 단계 상태 — BLE 로거`다. 모두 별도 의뢰라 후속 단계가 앞 단계의 상태를 덮어쓰지 않는다. DB 상태 컬럼을 강제로 덮는 대신 등록·검토·견적·수락·수동 입금 확인·착수·일정·문서·고객 응답 API를 순서대로 사용한다.

특정 단계만 재현하거나 기존 의뢰의 화면만 다시 찍을 수 있다.

```sh
pnpm --filter api develop:g-smoke run --steps=1,8,13
pnpm --filter api develop:g-smoke capture <실행번호>
pnpm --filter api develop:g-smoke status <실행번호>
```

`status`는 최초 저장한 상태와 현재 API 응답을 비교한다. 의뢰 상태 코드뿐 아니라 입금·자료 준비·공개 문서 버전/응답·진척도도 확인한다. `status-check.json`에 점검 결과를 남긴다. 견적 유효기간·검수 기간은 30일이며, 시간이 지나거나 직접 작업하면 상태가 바뀔 수 있다. 상태를 고정하려고 실제 업무 규칙을 끄지 않는다. 새 `run`으로 다시 준비한다.

## 외부 연동 처리

- 로컬 MySQL/MariaDB와 같은 G5 DB, `https://local-web.samplepcb.co.kr`, 비운영 실행만 허용한다. 운영·원격·DB 불일치는 거부한다.
- `.tmp/develop-g-smoke/registry/`의 실행 원장과 DB의 **전용 회원 ID + 실행 제목 표식 + G 소속**이 모두 맞는 의뢰만 테스트 대역을 사용한다. 일반 의뢰와 C 의뢰에는 적용하지 않는다. 인증/관리자 권한/고객 소유권 검사는 그대로다.
- 메일은 `mail/`에 로컬 수신 기록으로 남기며 외부 SMTP로 보내지 않는다. 일반 의뢰의 메일 설정이나 공통 AI 설정을 변경하지 않는다.
- 실제 PG checkout은 `LOCAL_SMOKE_PAYMENT`로 차단한다. 입금 상태는 관리자 수동 확인 API로 재현하며 영카트 주문·실 PG 거래를 만들지 않는다.
- 검토서는 시험용 수동 작성 자료를 공개한다. AI 동의는 false로 유지하며 LLM을 호출하지 않는다.
- 수행관리 첨부는 `files/`의 로컬 파일로 보관한다. 기존 인증/잔금 잠금을 통과한 다운로드 API만 파일을 반환하므로 서버 재시작 후에도 확인할 수 있다.
- 고객 브라우저 검증은 실제 PHP 로그인/세션을 사용한다. 관리자 자동 캡처는 도구 안의 서명된 테스트 세션을 사용하며 서버에 인증 우회 경로를 추가하지 않는다.

## 실행별 정리

```sh
pnpm --filter api develop:g-smoke cleanup <실행번호> --dry-run
pnpm --filter api develop:g-smoke cleanup <실행번호>
```

실행 원장의 의뢰 ID, 전용 회원, 제목 표식, G 소속을 확인한 뒤 해당 의뢰의 문서·작업 원장·견적·마일스톤·이벤트·파일·메일 DB 기록을 정리한다. 다른 실행/일반 의뢰가 포함되거나 실제 주문 연결·외부 첨부가 발견되면 중단한다. 전체 DB 복원·reset은 사용하지 않는다.

공통 테스트 고객 계정은 다음 실행에서 재사용한다. 보고서·스크린샷·상태 JSON·로컬 메일 기록은 정리 후에도 남는다. `.tmp`를 삭제하면 이 증거와 로컬 첨부가 사라지므로 의뢰가 남아 있는 동안 보존한다.

샘플PCB 플랫폼 연동

거버 뷰어에서 플랫폼으로 담기

거버 뷰어에서 [주문하기]·[견적요청]을 누르면 거버 파일과 사양을 플랫폼으로 보내 장바구니나 견적관리에 담습니다. 브라우저에서 호출 두 번이면 됩니다.

2026-10-11 기준 · 회색 칩은 누르면 복사되고, 코드 상자는 오른쪽 위 [복사] 버튼으로 복사합니다.

0한눈에 보기

STEP 1
로그인 확인 GET /spcb/api/me

로그인돼 있으면 10분짜리 토큰을 받습니다. 아니면 401입니다.

STEP 2
담기 요청 POST /api/pcb-projects

토큰과 함께 거버 zip · 썸네일 · 사양 JSON을 한 번에 보냅니다.

STEP 3
이동 redirectUrl

응답에 담긴 주소(장바구니 또는 견적관리)로 이동합니다.

동작 조건

  • 사용자의 브라우저에서 직접 호출합니다. 서버에서 대신 호출하면 로그인 쿠키가 없어 동작하지 않습니다.
  • 거버 뷰어 주소가 https://○○.samplepcb.co.kr 형태여야 합니다. 이 조건이면 플랫폼 로그인 쿠키가 자동으로 실립니다. 거버 뷰어가 어느 서버에 올라가 있는지는 상관없습니다.
  • 사용자는 플랫폼에 로그인돼 있어야 합니다. 플랫폼은 위쪽 입력칸의 주소이고, 예전 사이트(www.samplepcb.co.kr) 로그인과는 별개입니다.
  • 가격과 납기는 보내지 않습니다. 플랫폼이 사양으로 다시 계산하고, 그 값이 주문 금액이 됩니다.

2담기 요청

POST

헤더

  • 하나만 넣습니다.

3응답과 오류

HTTP 상태가 200이고 result가 true일 때만 성공입니다. 성공하면 data.redirectUrl로 이동합니다.

필드형식내용
projectId숫자플랫폼에 저장된 견적 번호.
quoteId문자열견적 계산 기록의 ID.
quoteStatus"priced" · "rfq"priced는 자동 견적 완료, rfq는 담당자가 견적을 내야 하는 건.
price숫자 · null플랫폼이 계산한 금액(원). rfq이면 null.
eta문자열예상 납기일 YYYY.MM.DD. 없으면 "".
cartAdded불리언장바구니에 담겼는지.
redirectUrl문자열이동할 주소. 주소를 직접 만들지 말고 이 값을 쓰세요.
unknownSpecKeys문자열 배열, 선택플랫폼이 모르는 spec 키가 있을 때만 옵니다. 키 이름을 확인해야 한다는 신호입니다.

어디로 이동하나

경우cartAdded이동하는 곳
flow가 order이고 자동 견적이 된 경우true장바구니 /shop/cart.php
그 밖 — flow가 rfq이거나 자동 견적이 안 되는 사양false견적관리 /shop/quotes

자동 견적은 category가 standard 또는 metalMask이고 orderCategory가 sample일 때만 됩니다. advance · flexible · 양산은 항상 rfq입니다.

오류

상태본문원인과 할 일
401{ "message": "로그인이 필요합니다", … }토큰이 없거나 만료됐습니다. 1단계를 다시 해서 한 번만 재시도합니다.
400{ "message": "gerber 파일 파트가 없습니다", … }본문이 multipart가 아니거나, gerber·payload 파트가 없거나, payload가 JSON이 아닙니다. message에 이유가 있습니다.
400{ "result": false, "error": "PAYLOAD_SCHEMA_MISMATCH", "issues": […] }payload 필드의 형식이 틀렸습니다. issues에 어느 필드인지 나옵니다.
413—파일이 100MB를 넘습니다.
502{ "result": false, "error": "FILE_UPLOAD_FAILED" }파일 보관에 실패했습니다. 저장된 것이 없으니 잠시 뒤 다시 보내면 됩니다.
500{ "message": "…", … }플랫폼 쪽 오류입니다.

구현할 때 지킬 순서

  1. 버튼을 누를 때마다 로그인 확인을 호출해 토큰을 새로 받습니다. 401이면 로그인 안내를 띄우고 끝냅니다.
  2. 거버 zip · 썸네일 · payload로 FormData를 만들어 담기 요청을 보냅니다.
  3. 담기 요청이 401이면 토큰을 새로 받아 같은 본문으로 한 번만 다시 보냅니다. 그래도 401이면 실패로 처리합니다.
  4. HTTP 200이고 result가 true이면 data.redirectUrl로 이동합니다.
  5. 그 밖의 응답과 네트워크 오류(fetch 예외)는 실패로 보고, 사용자에게 알린 뒤 버튼과 로딩 표시를 원래대로 돌려놓습니다.

4사양(spec) 키와 값

규칙

  • 값은 문자열로 보냅니다. 숫자도 받지만 예전 거버와 맞추려면 문자열이 안전합니다.
  • 선택 항목은 저장값을 대소문자까지 그대로 보냅니다. 화면 표시명(녹색)이 아니라 저장값(green)입니다.
  • 수량은 spec에 넣지 않습니다. 위쪽 qty 필드로 보냅니다.
  • 화면에서 숨긴 항목은 빼도 됩니다. 모르는 키를 보내도 거절하지 않고 저장하되, 응답의 unknownSpecKeys로 알려 줍니다.
  • 가로·세로는 mm입니다. 예: "68.580"
자동 견적이 조용히 빠지는 두 가지
  • differentDesign(파일 개수)이 비어 있거나 0이면 Standard 자동 견적이 되지 않고 견적요청으로 넘어갑니다. 최소 "1"을 보내세요.
  • panel은 배열을 안 하면 "no", 하면 "2x3"처럼 가로x세로로 보냅니다. "yes"만 보내면 자동 견적이 되지 않습니다.

키 목록

"예전 이름"은 예전 거버가 쓰던 전송 이름이 다를 때만 적었습니다. 예전 이름으로 사양을 모으고 있다면 이름만 이 표대로 바꾸고 값은 그대로 보내면 됩니다. 예전의 qty는 spec에서 빼서 위쪽 qty 필드에 정수로 넣습니다.

5점검 순서

  1. 로그인 확인이 되는지 — 플랫폼에 로그인한 뒤, 거버 뷰어 페이지의 개발자 도구 콘솔에서 아래를 실행합니다. 200이 찍히면 됩니다.
  2. 로그아웃 상태에서 제출 — 401을 받고 로그인 안내가 뜨는지 봅니다.
  3. Standard 샘플 [주문하기] — 응답이 cartAdded: true이고, 이동한 장바구니에 "Standard PCB · 파일명" 행이 가격과 함께 보이는지 봅니다.
  4. [견적요청] — 응답이 quoteStatus: "rfq"이고 견적관리로 이동하는지 봅니다.
  5. 제품군마다 한 번씩 제출 — 응답에 unknownSpecKeys가 없는지, 화면에 보여 준 가격과 응답의 price가 같은지 봅니다.
시험 제출도 실제로 저장됩니다 시험이 끝나면 플랫폼의 와 장바구니에서 지워 주세요.

6문제 해결

로그인했는데 로그인 확인이 401로 나옵니다

예전 사이트(www.samplepcb.co.kr)의 로그인 쿠키가 플랫폼 쿠키와 이름이 같아서 겹친 경우입니다. 두 사이트를 같은 브라우저에서 쓰면 생깁니다.

  • 시크릿 창을 열어 플랫폼에만 로그인하고 시험하거나,
  • 콘솔에서 아래 한 줄로 겹친 쿠키를 지운 뒤 새로고침합니다. 예전 사이트에서는 로그아웃됩니다.

콘솔에 CORS 오류가 납니다

  • 거버 뷰어 주소가 https://로 시작하고 .samplepcb.co.kr로 끝나는지 확인합니다. http://나 localhost에서는 로그인 확인이 막힙니다.
  • 로그인 확인 호출에 credentials: 'include'가 있는지 확인합니다.
  • 100MB를 넘는 파일은 서버가 받기 전에 끊어서, 오류 응답이 아니라 네트워크 오류나 CORS 오류처럼 보일 수 있습니다.

400 PAYLOAD_SCHEMA_MISMATCH

  • qty를 문자열로 보냈거나 0 이하입니다.
  • message 필드가 빠졌습니다. 요청사항이 없어도 ""를 넣어야 합니다.
  • orderCategory가 sample·mass가 아니거나, projectName이 빈 문자열입니다.
  • spec 값에 객체·배열·null·불리언이 들어 있습니다. 문자열이나 숫자만 됩니다.

400 "multipart/form-data 요청이어야 합니다"

Content-Type 헤더를 직접 넣었을 가능성이 큽니다. 헤더에서 빼고 FormData만 본문으로 넘기세요.

주문하기인데 가격이 null로 옵니다

  • category가 standard·metalMask가 아니거나 orderCategory가 mass이면 정상입니다.
  • Standard라면 differentDesign과 panel 값을 확인합니다.
  • Metal Mask라면 프레임이 있을 때 size가 위 표의 크기인지 확인합니다.

성공했는데 장바구니에 안 보입니다

응답의 cartAdded가 false이면 견적관리에 들어가 있습니다. true인데도 안 보이면, 이동한 브라우저가 제출할 때와 같은 계정으로 플랫폼에 로그인돼 있는지 확인합니다.

같은 주문의 견적서를 읽을 때마다 견적번호가 새로 만들어집니다. 아래는 주문 한 건(9cea45ca1704)을 내용 변경 없이 다섯 번 받아 본 결과입니다.

금액과 내용은 다섯 번 모두 같았습니다. 번호 가운데 여섯 자리가 받은 시각(시 · 분 · 초)입니다.

쉽게 말하면

같은 계약서를 복사할 때마다 문서 번호가 새로 찍히는 것과 같습니다. 복사본 다섯 장의 번호가 모두 달라서, 번호만 보고는 같은 계약서인지 알 수 없습니다. 그리고 "3번 복사본에 서명했다"고 말해도, 원본을 가진 쪽에는 3번이라는 문서가 없습니다.

이렇게 정리합니다 — samplepcb 가 보관한 번호를 씁니다

  1. 고객이 "견적 요청"을 눌러 보내신 견적번호를 samplepcb 가 그 견적의 번호로 보관합니다. 위 표에서는 22:41 의 Q-261118-224103-9cea45 입니다.
  2. SmartSMT 가 의뢰를 읽어 갈 때(6장) 그 번호를 돌려 드립니다. 견적서 화면에는 그 번호를 보여 주십시오.
  3. 번호를 고정하는 작업은 하지 않으셔도 됩니다. 가져오기에서 새 번호가 나와도 저희는 주문 번호로 같은 의뢰인지 가립니다.
부탁드리는 것 주문 번호(order_id)는 바뀌지 않게 해 주십시오. 의뢰를 다시 불러 고친 뒤 견적 요청을 해도 같은 주문 번호여야 합니다.

6의뢰 데이터 연동

지금 SmartSMT 의 "내 의뢰" 목록과 원본 파일은 고객 브라우저에 저장됩니다. 그래서 다른 PC 나 다른 브라우저에서는 의뢰가 보이지 않습니다. 협의한 대로, 의뢰 데이터를 samplepcb 한 곳에 보관하고 SmartSMT 는 필요할 때 읽어 가도록 맞춥니다. 담당자가 확정한 금액도 같은 길로 읽어 가므로, 담당자 견적 전송(POST /api/pricing/received)은 쓰지 않습니다.

무엇맡는 곳
계산 · 작업 화면(PCB · PART · SMT · Order)SmartSMT
의뢰 기록 보관 — 견적서 · 원본 파일 · 작업 상태samplepcb
담당자 확정 — 항목별 금액, 배송비samplepcb 관리자
내 의뢰 목록 · 다시 부르기 · 견적서 표시SmartSMT 화면 (데이터는 samplepcb 에서 읽음)
  1. 고객이 "견적 요청"을 누릅니다.
  2. SmartSMT 가 견적서와 함께 작업 상태 · 원본 파일을 보냅니다. 지금 쓰시는 POST /api/smartsmt/quotes 에 파트 하나가 늘어납니다 — 6.1
  3. samplepcb 가 받은 것을 보관합니다.
  4. 고객이 "내 의뢰"를 엽니다.
  5. SmartSMT 가 그 회원의 의뢰 목록을 samplepcb 에서 읽습니다. 6.2 의 목록 주소
  6. 고객이 의뢰의 "진행 상태"를 누릅니다(다시 부르기).
  7. SmartSMT 가 작업 상태와 원본 파일을 samplepcb 에서 읽어 작업 화면을 복원합니다. 6.2 의 한 건 · 파일 주소
  8. samplepcb 담당자가 항목별로 금액을 고쳐 확정합니다. 합계는 통합 견적서와 같은 식으로 다시 계산됩니다.
  9. 고객이 "검토서"나 견적서를 엽니다.
  10. SmartSMT 가 한 건을 다시 읽으면 확정 금액이 담긴 견적서가 함께 옵니다. 6.3

6.2 samplepcb 가 제공하는 주소 samplepcb 제공

SmartSMT 서버가 부릅니다(브라우저가 직접 부르지 않습니다). 인증은 견적서 전송과 같은 토큰입니다 — Authorization: Bearer {토큰}, iss = smartsmt, aud = samplepcb.

쓰임주소 (https://new.samplepcb.co.kr)
내 의뢰 목록GET /api/smartsmt/orders?owner={회원 아이디}&page=1&page_size=20
의뢰 한 건GET /api/smartsmt/orders/{order_id}?owner={회원 아이디}
원본 파일GET /api/smartsmt/orders/{order_id}/files/{part}?owner={회원 아이디}
owner 는 꼭 넣습니다 로그인한 회원의 아이디(로그인 토큰의 sub)입니다. samplepcb 는 그 회원의 의뢰만 내주고, 주인이 다르면 없는 의뢰로 답합니다(404). 화면이 보낸 값을 그대로 쓰지 말고 SmartSMT 세션의 회원 아이디를 넣어 주십시오.

오류 본문은 견적서 전송과 같은 모양입니다 — {"detail":{"reason":"…","message":"…"}}

6.3 확정 금액이 담긴 견적서 confirmed_envelope

samplepcb 담당자는 주문 화면의 결과를 놓고 항목별로 금액을 고치거나 채웁니다(배송비 포함). 총액은 직접 고치지 않고 통합 견적서와 같은 식으로 다시 계산합니다 — 직접공정비(줄의 합) → 간접비 → 기업이윤 → PCB · 부품 · 배송을 더해 공급가액 → 부가세. 요율은 보내신 견적서의 header.controls 값을 씁니다. confirmed_envelope 는 보내신 견적서와 같은 모양이라, 지금 견적서 화면에 그대로 넣어 그리실 수 있습니다. 아래 칸만 바뀝니다.

칸바뀌는 내용
quote.lines[].amount담당자가 정한 금액. 고치지 않은 줄은 보내신 값 그대로, 비어 있던 줄은 채워집니다
quote.lines[].status빈 글자 (확정)
quote.subtotals[]amount · known_amount 를 줄의 합으로 다시 계산, unknown_count 는 0
quote.integrated.blocks[].amountPCB · 부품 · 배송의 확정 금액. 배송비는 samplepcb 가 정합니다
quote.direct_cost · indirect_cost · profit · supply_price · vat · total다시 계산한 SMT 작업비
quote.integrated.totals 의 supply_price · vat · total다시 계산한 통합 합계 — 견적서의 공급가액 · 부가세 · 총합계
quote.quote_statusCALCULATED
quote.unknown_lines · quote.integrated.blocked_by빈 배열
맨 위 review_status · customer_note · reviewed_at확정 표시 · 고객 안내 글 · 확정한 시각

그 밖의 칸(header · 추정 금액 estimated_* · 경고 등)은 보내신 값 그대로입니다.

6.4 화면에서 바뀌는 것 SmartSMT

화면지금바뀐 뒤
내 의뢰 목록브라우저 저장소견적 요청한 의뢰는 목록 주소에서 읽습니다. 상태는 review_status(검토중 · 확정), 확정이면 confirmed_total 을 보입니다
진행 상태
(다시 부르기)		브라우저에 저장한 파일 · 상태로 복원한 건 주소의 state 와 원본 파일로 복원합니다. 주문 번호는 그대로입니다
검토서 · 견적서가견적확정이면 confirmed_envelope 로 그리고 customer_note 를 함께 보입니다. 확정 전이면 지금처럼 가견적과 "검토중"
열기 주소 새로—samplepcb 견적관리에서 들어오는 주소입니다 — 6.5
  • samplepcb 가 답하지 않을 때(시간 초과 · 5xx)는 목록을 비우지 말고 "잠시 후 다시 시도" 안내를 보여 주십시오.
  • 가견적 화면에는 "확정 견적은 담당자 검토 후 안내됩니다" 같은 안내를 부탁드립니다. 가견적과 확정 금액이 다를 수 있습니다.

6.5 samplepcb 견적관리에서 SmartSMT 화면으로

samplepcb 마이페이지의 "견적관리"에 SMT 의뢰가 PCB · 부품 견적과 함께 보이게 합니다. 고객이 누르면 SmartSMT 의 열기 주소로 이동합니다. 

https://smteyes.samplepcb.co.kr/open?order={order_id}     # 제안 — 다른 주소가 편하시면 알려 주십시오
  1. SmartSMT 세션이 없으면 로그인 인계를 거칩니다. 요청서 4장. 돌아올 자리는 state 에 실어 두시면 됩니다
  2. 한 건 주소로 의뢰를 읽습니다(owner = 세션의 회원 아이디). 404 면 "의뢰를 찾을 수 없습니다" 안내
  3. 확정된 의뢰는 견적서(확정 금액)를, 검토 중인 의뢰는 작업 화면을 엽니다. 작업 화면은 다시 부르기와 같습니다

7견적서에 부품 줄 넣기

지금 견적서의 부품은 합계만 옵니다(PARTS 블록의 amount). 담당자가 부품별 수량 · 단가를 확인하고 고칠 수 있도록, BOM 견적서에 나오는 부품 줄을 견적서에 함께 실어 주십시오.

위치(제안): quote.integrated.blocks[] 의 PARTS 블록 안 detail.lines 배열.

칸종류내용
refs문자 배열REF (예: ["C1","C2"])
name문자품명 (품번 또는 BOM 표기)
spec문자제조사 · 규격
mount문자SMT · THT(수삽) · NC(미실장)
supply문자TURNKEY(도급) · CUSTOMER(사급)
qty숫자구매 수량 — 세트 수량을 곱한 총 수량
unit_price숫자 · null단가(원)
amount숫자 · null금액(원). 가격이 없으면 null
match문자MATCHED · REVIEW · UNMATCHED · NOSTOCK · EXCLUDED
  • 줄 금액의 합이 PARTS 블록의 amount 와 같아야 합니다. 미실장으로 뺀 부품은 줄에 넣지 않거나 금액을 0 으로 둡니다.
  • 담당자는 부품별 구매 수량과 단가만 고칩니다. 세트 수량 · 미실장 · 사급 전환처럼 SMT 계산이 함께 바뀌는 수정은 SmartSMT 화면에서 하고 다시 견적 요청을 합니다.
  • 칸 이름이나 놓는 자리가 다르면 알려 주십시오. 맞추겠습니다.

8첨부 파트

파트 이름을 미리 정해 두지 않도록 바꿨습니다. packing · stackup · report 를 포함해, 아래 규칙에 맞는 파일 파트는 모두 받아 보관합니다.

항목규칙
파트 이름소문자로 시작하고 소문자 · 숫자 · 밑줄만, 32자까지 (예: stackup, report_2)
개수견적서 하나에 파일 12개까지
형식가리지 않습니다 (받은 그대로 보관)
크기요청 하나의 전체 크기 100MB 까지
대조견적서 header.files 에 있으면 크기 · 해시를 대조합니다(다르면 400 FILE_MISMATCH). 목록에 없는 파일도 받습니다
  • 모르는 파트가 와도 거절하지 않습니다(200). 이름이 규칙에 맞는 파일은 저장하고, 규칙에 맞지 않는 파일과 모르는 글자 파트는 읽지 않고 넘어갑니다.
  • 새 파트를 보내기 시작하실 때 미리 알려 주실 필요는 없습니다. 무엇이 든 파일인지만 한 줄 알려 주시면 관리자 화면의 이름을 맞추겠습니다.
  • 작업 상태(state)는 파일이 아니라 값 파트입니다 — 6.1.

9문서 변경 사항 확인

알려 주신 것저희 쪽
견적서 가져가기의 409 NOT_PUBLISHABLE 없어짐 — 확정 전 견적도 보냄확인했습니다. 확정 전 견적도 그대로 받고, 정해지지 않은 금액(null)은 "미정"으로 둡니다
POST /api/pricing/received 에 토큰을 붙이면 담당자 견적으로 저장쓰지 않습니다. 확정 견적은 SmartSMT 가 samplepcb 에서 읽어 가는 방식으로 합니다(6장)
  • 견적서에 함께 오는 추정 금액(estimated_total 등)은 관리자 화면에 "추정"이라고 이름을 붙여 보입니다. 고객 화면의 "최종합계"와 같은 값입니다.
  • 받은 견적서는 envelope_version 9 로, 「견적서 전송 양식 0.3」과 칸이 조금 달랐습니다(수량 칸 이름 · 추정 금액 · 주문 공정 등). 받은 견적서를 보고 저희 화면을 맞췄습니다. 앞으로 칸이나 코드가 늘어도 거절하지 않습니다.

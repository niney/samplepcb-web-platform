부탁 ①

좌표 파일을 함께 보내 주십시오

전송에 cpl 파트가 빠져 있습니다. 함께 보내도록 수정 부탁드립니다.

부탁 ②

견적번호를 고정해 주십시오

같은 견적서를 읽을 때마다 번호가 달라집니다. 고정이 어렵다면 번호는 저희가 관리하겠습니다.

5장 · 7장의 내용은 이 문서를 받으신 시점에 https://new.samplepcb.co.kr 에 반영돼 있습니다.

2026-11-18 에 받은 견적서는 세 건이고, 모두 200 으로 받아 저장했습니다. 받은 파일의 크기와 해시는 견적서의 header.files 와 같았습니다.

세 건 모두 cpl 파트가 오지 않았습니다. 아래는 22:41 의 주문(9cea45ca1704)에서 화면에 올린 파일과 전송된 파일입니다.

부탁드리는 것 좌표 파일도 cpl 파트로 함께 보내도록 수정 부탁드립니다. 견적서의 header.files 에도 함께 넣어 주십시오.

저희 쪽은 파일 형식을 가리지 않고 받습니다.

4부탁 ② 견적번호

같은 주문의 견적서를 읽을 때마다 견적번호가 새로 만들어집니다. 아래는 주문 한 건(9cea45ca1704)을 내용 변경 없이 다섯 번 받아 본 결과입니다.

금액과 내용은 다섯 번 모두 같았습니다. 번호 가운데 여섯 자리가 받은 시각(시 · 분 · 초)입니다.

쉽게 말하면

같은 계약서를 복사할 때마다 문서 번호가 새로 찍히는 것과 같습니다. 복사본 다섯 장의 번호가 모두 달라서, 번호만 보고는 같은 계약서인지 알 수 없습니다. 그리고 "3번 복사본에 서명했다"고 말해도, 원본을 가진 쪽에는 3번이라는 문서가 없습니다.

무엇이 곤란한가

  1. 같은 견적인지 가릴 수 없습니다. 저희는 견적번호로 "이미 받은 견적"을 가립니다. 담당자가 '견적서 가져오기'를 누를 때마다 번호가 달라서, 같은 견적이 새 견적으로 계속 쌓입니다.
  2. 어느 견적을 확정했는지 가리킬 수 없습니다. 담당자가 22:41 에 받은 견적을 보고 확정해 돌려보내도(6장), SmartSMT 쪽에는 그 번호의 견적이 남아 있지 않습니다.

부탁드리는 것 — 둘 중 하나를 골라 주십시오

내용바뀌는 쪽
가. 번호 고정
먼저 부탁드리는 안		 고객이 "견적 요청"을 누른 때의 번호를 그 견적의 번호로 정합니다. 주문 내용이 바뀌기 전에는 가져오기에서도 같은 번호를 돌려줍니다. 내용이 바뀌어 다시 요청하면 새 번호를 붙입니다. SmartSMT
나. samplepcb 가 관리
가 안이 어려울 때		 견적 기록과 견적번호는 samplepcb 가 관리합니다. SmartSMT 는 계산과 화면을 맡고, 두 서버가 주고받을 때는 주문 번호(order_id)만 공통으로 씁니다. 담당자가 확정한 견적에는 저희가 번호를 붙여 보냅니다. samplepcb

"가"로 해 주시면 위 표의 22:41 이후 가져오기는 Q-261118-224103-9cea45 를 그대로 돌려주게 됩니다. "나"로 가도 됩니다 — 이때 SmartSMT 에서 바꾸실 것은 없고, 저희가 견적번호 대신 주문 번호와 내용으로 가리도록 고칩니다. 어느 쪽이든 주문 번호는 바뀌지 않는다는 것만 확인해 주십시오.

5로그인 인계 회원 정보

요청하신 칸 이름 그대로 로그인 토큰에 넣었습니다. 값이 없는 회원은 칸 자체가 없습니다(빈 글자를 보내지 않습니다).

칸내용들어가는 때
company회사명회원 정보에 회사명이 있을 때
phone연락처 (휴대폰, 없으면 전화번호)값이 있을 때
email이메일아이디와 다를 때 — 아이디가 이메일인 회원이 많습니다
department부서넘기지 않습니다 — samplepcb 회원 정보에 부서가 없습니다

지켜 주실 것
  • 말씀하신 대로 이 값들은 저장하지 않고 로그인 중에 견적서 수신란 표시에만 씁니다.
  • 로그인 토큰은 주소(?token=…)에 실려 갑니다. 서버 접속 기록 · 분석 도구에 token 값을 남기지 않습니다(요청서 4.5).

토큰 검사 방법과 그 밖의 칸은 바뀌지 않았습니다. 「SmartSMT 인증 연동 요청서」 판 0.3 의 4.2 에 같은 내용을 적었습니다.

6담당자 견적 전송 (제안)

받은 견적은 세 건 모두 REVIEW_REQUIRED 이고 확정 금액(total)이 비어 있었습니다 — 부품 · 배송 · SMT 작업비가 아직 정해지지 않아서입니다. 저희 담당자는 주문 화면의 결과를 그대로 놓고 항목별로 금액을 고치거나 채워서 확정합니다. 총액은 직접 고치지 않고, 통합 견적서와 같은 식(직접공정비 → 간접비 → 기업이윤 → 부가세)으로 다시 계산합니다. 배송비는 samplepcb 가 정합니다. 이 기준으로 보낼 모양을 제안드립니다.

항목제안
주소POST https://smteyes.samplepcb.co.kr/api/pricing/received
인증Authorization: Bearer {토큰} — iss = samplepcb, aud = smartsmt (견적서 가져오기와 같은 토큰)
본문application/json — 받은 견적서 JSON 그대로. header(주문 번호 · 회원 아이디)는 바꾸지 않습니다
담당자가 고치는 칸견적 줄의 금액 quote.lines[].amount, 블록의 금액 quote.integrated.blocks[].amount(PCB · 부품 · 배송)
다시 계산해 채우는 칸quote 의 direct_cost · indirect_cost · profit · supply_price · vat · total 과 quote.integrated.totals 의 supply_price · vat · total. 요율은 견적서의 header.controls 값을 씁니다
맨 위 추가 칸review_status · customer_note · reviewed_at (아래 표)
응답stored 가 true 일 때만 성공으로 봅니다. 그 밖(stored: false · 401)은 실패로 보고 담당자에게 알립니다
추가 칸종류내용
review_status문자담당자 처리 상태 — CONFIRMED(확정) · HOLD(보류, 고객 확인이 필요함)
customer_note문자고객 안내 글. 없으면 빈 글자
reviewed_at문자담당자가 처리한 시각 (ISO 8601, 예: 2026-11-19T10:30:00+09:00)
만들기 전에 확인 부탁드리는 세 가지
  1. 고객 화면이 읽는 칸 위 표의 칸을 채워 보내면 됩니까? quote_status · blocked_by · 줄의 status 도 저희가 바꿔 보내야 합니까?
  2. 토큰의 aud 위 제안대로 smartsmt 로 보내면 됩니까?
  3. 다시 보낼 때 같은 주문에 한 번 더 보내면 마지막 것으로 바뀝니까?

칸 이름이나 값이 다르면 알려 주십시오. 맞추겠습니다.

7첨부 파트

파트 이름을 미리 정해 두지 않도록 바꿨습니다. packing · stackup · report 를 포함해, 아래 규칙에 맞는 파일 파트는 모두 받아 보관합니다.

항목규칙
파트 이름소문자로 시작하고 소문자 · 숫자 · 밑줄만, 32자까지 (예: stackup, report_2)
개수견적서 하나에 파일 12개까지
형식가리지 않습니다 (받은 그대로 보관)
크기요청 하나의 전체 크기 100MB 까지
대조견적서 header.files 에 있으면 크기 · 해시를 대조합니다(다르면 400 FILE_MISMATCH). 목록에 없는 파일도 받습니다
  • 모르는 파트가 와도 거절하지 않습니다(200). 이름이 규칙에 맞는 파일은 저장하고, 규칙에 맞지 않는 파일과 모르는 글자 파트는 읽지 않고 넘어갑니다.
  • 새 파트를 보내기 시작하실 때 미리 알려 주실 필요는 없습니다. 무엇이 든 파일인지만 한 줄 알려 주시면 관리자 화면의 이름을 맞추겠습니다.

8문서 변경 사항 확인

알려 주신 것저희 쪽
견적서 가져가기의 409 NOT_PUBLISHABLE 없어짐 — 확정 전 견적도 보냄확인했습니다. 확정 전 견적도 그대로 받고, 정해지지 않은 금액(null)은 "미정"으로 둡니다
POST /api/pricing/received 에 토큰을 붙이면 담당자 견적으로 저장6장의 제안대로 쓰겠습니다
  • 견적서에 함께 오는 추정 금액(estimated_total 등)은 관리자 화면에 "추정"이라고 이름을 붙여 보입니다. 고객 화면의 "최종합계"와 같은 값입니다.
  • 받은 견적서는 envelope_version 9 로, 「견적서 전송 양식 0.3」과 칸이 조금 달랐습니다(수량 칸 이름 · 추정 금액 · 주문 공정 등). 받은 견적서를 보고 저희 화면을 맞췄습니다. 앞으로 칸이나 코드가 늘어도 거절하지 않습니다.

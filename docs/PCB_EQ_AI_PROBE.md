> 2026-10-11 · 정본 설계 `docs/PCB_PARTNER_TRACK.md` 「D20 설계」 · 계약 `packages/api-contract/src/schemas/pcb-eq-review.ts`(`PcbEqDraft`)

## 1. 목적

협력사(중국 공장)가 올린 EQ 엑셀(문항 N개 × 선택지 A/B/C × 그림)을 관리자 EQ 작업공간의 **문항 초안**(`PcbEqDraft`)으로
바꾸는 길을 정한다 — ① 엑셀에서 셀·그림을 꺼내는 일이 Node 만으로 되나 ② 문항 구조를 읽는 데 LLM 이 필요한가, 표 규칙
(템플릿 파서)으로 충분한가 ③ LLM 을 쓴다면 어느 모델·think·프롬프트인가. 초안은 **관리자 검토를 거쳐야 고객에게 간다**
(D20-1) — 여기서 재는 것은 "관리자가 고칠 것이 얼마나 남나"다.

## 3. 방법

### 3.1 파이프라인

```
EQ 첨부(.xls/.xlsx/.zip)
 → extractEqWorkbook   셀 텍스트·병합·그림(시트+앵커 셀) — LLM 없음, 결정적
 → serializeForLlm     표를 짧은 글로(R8 A:… | D:…, 병합 힌트, [IMG img-2 sheet="图 1"])
 → (A) LLM 전체 분석   buildEqParsePrompt + format=EQ_DRAFT_JSON_SCHEMA → extractJsonObject → coerceEqDraft → PcbEqDraft
 → (B) 템플릿 파서     parseEqTemplate — 머리글 낱말로 열 역할, 번호 칸으로 블록, 선택지 줄/한 셀 파싱(번역 없음)
 → (C) B 구조 + LLM 번역만  buildEqTranslatePrompt(질문·선택지 원문만) → mergeTranslation(구조는 템플릿이 이김)
```

그림은 LLM 이 아니라 추출기가 꺼낸다 — LLM 은 자리표시 id(`img-N`)로 **어느 문항의 그림인지만** 고른다(`figureRefs`).

### 3.2 추출기

- `.xls`(BIFF8): 셀·병합은 SheetJS 0.20.3(CDN tarball — npm 레지스트리 0.18.5 는 CVE-2023-30533·CVE-2024-22363), 그림은
  `cfb` 로 Workbook 스트림을 열고 직접 걷는다 — 전역 MSODRAWINGGROUP(+CONTINUE) = OfficeArt BStore(FBSE→BLIP, PNG/JPEG/
  EMF/WMF), 시트 구간(BOUNDSHEET.lbPlyPos 부터) MSODRAWING 을 이어 붙여 SpContainer 마다 FOPT pib(0x0104) + ClientAnchor
  (0xF010) 왼쪽 위 셀. 그룹 도형은 그룹 앵커를 물려받는다. FILEPASS(암호)는 경고.
- `.xlsx`: 셀은 SheetJS, 그림은 패키지(zip)를 fflate 로 풀어 DrawingML 직접 파싱 — ① 떠 있는 그림(twoCell/oneCell/absolute
  Anchor) ② **WPS 셀 안 그림**(`=DISPIMG("ID_…",1)` + `xl/cellimages.xml` — 중국 공장은 WPS 를 많이 쓴다) ③ **Excel 365
  '셀에 배치'**(셀 `vm` → metadata → richData). ②③은 실파일이 없어 단위 테스트에서 부품을 덧붙여 재현했다.
- `.zip`: 안의 첫 `.xls/.xlsx`(macOS 메타·`~$` 임시 제외), 여럿이면 경고. 중첩 zip 은 따라가지 않는다.
- 그 밖: 텍스트로 보이면(HTML/CSV 로 내보낸 '가짜 xls') SheetJS 로 셀만, 바이너리면 경고.
- 그림 id = 시트 순서 → 앵커(행·열) 순서로 `img-1…` — 형식이 달라도 같은 배치면 같은 id.
- 엑셀 날짜 일련값(서식이 날짜인 숫자 셀) → `YYYY-MM-DD`(UTC 산술, 1904 체계 처리).
- 안전 상한: 입력 20MB · zip 안 통합문서 해제 40MB(누적) · 시트 40 · 행 1000 · 열 80 · 그림 30장·장당 8MB. **throw 하지
  않는다** — 암호·손상·미지원·상한 초과는 `warnings` 에 쌓고 가능한 만큼 돌려준다.
- 실측: 실샘플 `.xls`(시트 12·병합 133·그림 5) **15ms**(동기). 포털 업로드 경로에서 바로 불러도 된다(상한 기준 수십 ms 추정).

### 3.3 직렬화(LLM 입력)

- 빈 행 제거, `R8 A:… | D:…`(빈 셀 생략), 셀 안 줄바꿈 `⏎`, 연속 공백 하나, 셀당 1,500자 상한.
- 병합은 힌트만: 세로 병합은 행 구간별로 묶어 한 줄(`R8~R10[ABCDEHIJKLMN]` — 문항 블록이 보인다), 가로 병합 앞 20개.
- 메인 시트(앞 40행 EQ 머리글 낱말 수 최다) 전부 → 그림 전용 시트(짧은 문구 ≤3 + 그림)는 자리표시만 → 그림·내용 없는
  시트는 이름만 → 나머지는 짧으면(≤1,500자) 통째, 메인이 이름으로 부르면 4,000자까지, 아니면 앞 6행 엿보기.
- 그림은 걸친 행 바로 뒤에 `[IMG img-2 sheet="图 1" at=C1]`.
- 실샘플 3,528자(시트 12개 중 적층표 템플릿 `Sheet1` 은 앞부분만), 픽스처 585~5,664자. 프롬프트 전체(규칙·유형·용어집 포함)는
  3,603~8,682자.

### 3.4 프롬프트

- **v1(`eq-parse-v1`)**: 역할(EQ 표 → 고객용 문항 JSON) · 입력 표기 설명 · 규칙 11개(빈 슬롯·빈 선택지 버림 / 번호 원문 그대로·
  결번 채우지 않음 / `questionOrig` 글자 그대로 복사·이전 회차 답 제외 / 한국어 존댓말·없는 내용 금지·我司=제조사·贵司=귀사 /
  선택지 기호 원문 그대로·없을 때만 A,B / `requiresComment`(请贵司指示·please advise 류) / `recommended` 는 **글로 적힌 권장만** /
  유형 칸 우선 / `figureRefs` 는 입력 id 만·로고 제외 / 머리 3칸 없으면 null / JSON 하나만) · 유형 16종 · 용어집 38항(`glossary.ts`,
  채점과 공용) · 출력 모양 예시. JSON 스키마(`format`)는 **원문을 먼저 베끼고 번역을 쓰도록** 속성 순서를
  `questionOrig → question`, `labelOrig → label` 로 둔다.
- **v2(`eq-parse-v2`)**: 2단에서 여러 모델이 공통으로 틀린 두 곳만 규칙을 보탰다(§5.7) — ① "`E:`·`F:` 같은 **열 문자는 셀 위치일
  뿐 선택지 기호가 아니다**, 선택지가 열마다 나뉜 표는 열 머리글의 기호를 쓴다" ② "숫자 기호(Option 1, 1))는 숫자 그대로 —
  A·B 로 바꾸지 않는다, `labelOrig` 에서 기호 머리(`A.`·`Option 1:`·`□`)는 뺀다" + 질문이 중문·영문 두 칸이면 이어 넣기.
- 번역만 프롬프트(`eq-translate-v1`)는 템플릿 구조의 원문·기호만 넘긴다.

### 3.5 채점(`probe-score.ts`, 정답 대비 결정적)

- 계약: 원출력이 `PcbEqDraft` 를 그대로 통과(계약(원)) / `coerceEqDraft`(형 변환·빈 값·모르는 그림 id 제거만 — 지어내지 않음)
  뒤 통과.
- 문항 짝짓기: `factoryNo` 정규화 일치 → 남은 것은 원문 유사도(2-gram Dice ≥0.5). 재현율·정밀도.
- 짝지은 문항마다: 유형(정답 또는 허용 대체 유형 — 공장 분류와 내용이 갈리는 문항), 선택지 기호 집합 일치,
  `requiresComment`·`recommended` 기호별 일치율, `figureRefs` 집합 일치, 빈 슬롯 번호가 하나도 안 나왔나.
- **지어내기 검사**: 예측 `questionOrig` 의 3-gram 중 LLM 입력 원문에 있는 비율(충실도, 0.9 이상이면 1) — 0.5 미만 문항 수를
  '지어냄'으로 센다.
- 용어집 준수: 정답 원문에 걸린 용어집 항목마다 예측 한국어(질문+선택지)에 기본 표기나 허용 표기가 있나.
- 머리(고객 품번·공장 품번·작성일) 일치율. 지연(p50/p95, 재시도 포함 합계)·버린 사고 토큰 글자 수. 토큰 수는
  `ollamaChatDetailed` 가 eval_count 를 돌려주지 않아 재지 못했다(§9).
- **종합(0~100)** = 100 × [0.7 × 구조 + 0.15 × 원문 충실 + 0.15 × 용어집] × (원출력 계약 통과 1 / 정리 후에만 통과 0.9),
  구조 = 0.3 재현 + 0.2 정밀 + 0.15 유형 + 0.2 선택지(기호 0.5 + 의견필수 0.3 + 권장 0.2) + 0.15 그림. 계약 실패는 0.
- 번역 품질은 숫자로 재지 않는다 — `translations.md` 에 정답(참조 번역)과 모델 출력을 나란히 저장한다(§5.8 표본). 보조로
  **수치·파일명 보존율**(원문의 두 자리 이상 수·소수·따옴표 속 파일명이 번역에 남았나)을 따로 셌다.

### 3.6 실행 조건

- 연결: `apps/api/.env` 의 `AI_BASE_URL=https://ollama.com` 직결(운영과 같은 경로) + `AI_API_KEY`. 모델 목록은 실행 직전
  `GET /api/tags` 로 확인(2026-10-11: 후보 15개 모두 있음, 그 밖 `mistral-large-3:675b`·`gpt-oss:20b`·`nemotron-3-nano:30b`).
- 호출은 출하 코드 그대로: `chatWithOptionFallback` → `ollamaChatDetailed`(stream) → `extractJsonObject`. 파싱 실패·일시
  오류는 1회 재시도. temperature 0, seed 없음, `format` = JSON 스키마, 호출당 타임아웃 600초.
- 동시성: 1단과 2단 앞 91건은 3, 그 뒤는 10(사용자 확인 — ollama.com 은 동시 10까지). 429·5xx 백오프(30초 뒤 재시도·
  동시성 낮춤)는 넣었으나 **한 번도 걸리지 않았다**. 동시성 3 과 10 의 지연은 같은 모델에서 갈리지 않았다(§5.4) — 지연 표는
  두 구간을 합친 값이다.
- 규모: LLM 작업 543건(호출 시도 551) — 1단 90 · 2단 본실행 180 · think 비교 60 · 조합 48 · 프롬프트 v2 120 · deepseek off 45.

## 4. 코퍼스

### 7.1 기본 설정

### 7.2 역할 분담 — 무엇이 LLM 이고 무엇이 아닌가

| 일 | 맡는 것 | 이유 |
|---|---|---|
| 셀·병합·그림 바이트·그림 위치·날짜 | 추출기(결정적) | 15ms, 경고 0. LLM 은 그림을 보지 않는다 |
| 문항 나누기·선택지 기호·의견필수·그림 연결 | **LLM 전체 분석** | 모르는 양식에서도 맞다(홀드아웃 100). 템플릿은 양식을 알 때만 |
| 한국어 번역·유형 | LLM | — |
| 구조 대조 | 템플릿 파서(통할 때) | LLM 구조와 지문이 다르면 그 문항에 '구조 확인 필요' — LLM 구조 오답 27건 전부 드러남 |
| 빈 선택지·빈 슬롯·모르는 그림 id | `coerceEqDraft` | 결정적, 지어내지 않음 |
| 번역이 수치·파일명을 뺐나 | `findDroppedFacts` | 빠진 값이 있으면 그 문항에 '번역 확인 필요'(실샘플 4번 유형) |
| 작성일 보충·LLM 꺼짐/실패 시 초안 | 템플릿 파서 | 번역 없는 초안이라도 수동 입력보다 낫다 |
| 로고 등 무관 그림 | LLM 이 안 고른 그림 = 올리지 않음 | 2단 전 실행에서 로고·도장·QR 을 문항에 붙인 경우 0 |
| 최종 판정 | **관리자**(D20-1) | 유형·권장·번역 어감은 사람이 본다 |

조합(템플릿 구조 + 번역만)을 주 경로로 쓰지 않는다 — 지연 2초를 아끼고 양식 의존을 들인다(§5.6). 공장 양식이 한두 종으로
굳으면 그때 다시 본다.

## 9. 계약·공용 코드 제안(내 소유 밖 — 제안만)

- **`PcbEqDraft` 에 문항별 `notes?: string[]`(또는 `flags`)** — '구조 확인 필요'·'번역 확인 필요'·'선택지 없음' 같은 결정적 검사
  결과를 초안과 함께 실을 자리. 지금 계약에는 문항 단위 경고를 둘 곳이 없다.
- **개정 회차 표시(`change`)는 AI 초안에 넣지 말 것** — 직전 회차와의 비교는 `factoryNo`·`questionOrig` 유사도로 결정적으로
  낼 수 있다(e 에서 번호·원문이 그대로 재현됨). LLM 에게 "바뀐 문항"을 묻지 않아도 된다.
- **`PcbEqItemOption.key` max 4** 는 실측 범위(A·1·…)에 충분하다. 다만 원문에 기호가 없는 양식(체크박스)은 A·B 를 붙이므로
  협력사 회신서에 "기호는 당사가 붙임" 표기가 있어야 공장이 헷갈리지 않는다(l).
- `ollamaChatDetailed` 가 스트림 마지막 줄의 `prompt_eval_count`·`eval_count` 를 돌려주면 토큰·비용을 잴 수 있다(이번엔 글자
  수로만).
- 공용 결함 두 건은 이미 고쳐졌다 — `extractJsonObject` 열0 원소 오선택(31758cb85) · `chatWithOptionFallback` 429 오분류
  (a4d1b8745). `lib/pcb-eq-extract/prompt.ts` 의 `parseEqJson` 은 계측용 모양 검사로 남겼다(발동 0 이 정상).

## 10. 남은 의문

1. **실샘플 정답 확인**(`.tmp/eq-probe/real/EQ-L050AKM1001.gold.json`) — 2번 유형(공장 `outline`, 내용은 패널 → 둘 다 정답
   처리)·4번 그림 없음·참조 번역 문장. 사용자 확인 전이다.
2. **번역 문체** — 이중언어 문항을 합쳐 짧게(kimi-k3) 대 둘 다 옮겨 빠짐없이(deepseek 기본·glm). §5.8 표를 보고 사용자가
   고르면 프롬프트에 한 줄로 고정할 수 있다("중문·영문이 같은 뜻이면 한 번만, 한쪽에만 있는 정보는 반드시 남긴다" — 미측정).
3. **`recommended` 규칙** — "질문에서 제조사가 권한 안을 받아들이는 선택지"를 권장으로 칠지. 지금은 치지 않는다.
4. **실제 공장 양식 분포** — 실샘플이 하나뿐이다. 운영에서 EQ 첨부가 쌓이면 추출 경고율·템플릿 통과율·관리자 수정률을 다시
   잰다(WPS 셀 안 그림·Excel 365 셀 그림·암호 파일은 실파일로 못 봤다).
5. **그림 형식** — 실샘플은 전부 PNG 였다. EMF/WMF·DIB 로 붙인 캡처는 꺼내기만 하고(확장자 `emf`/`wmf`/`bin`) 변환하지 않는다.
6. 고객 의견 **영문 역번역**(D20 P2 의 나머지 반)은 이번에 재지 않았다.

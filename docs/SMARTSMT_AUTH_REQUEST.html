SmartSMT 를 samplepcb 로그인으로 쓰고, 두 서버가 서로를 부를 때 쓸 인증 방식을 제안합니다. 두 서버가 비밀 문자열 하나를 나눠 갖고, 그것으로 서명한 2분짜리 토큰(JWT)을 주고받는 방식입니다. 구현이 어려운 부분이 있으면 알려 주십시오. 맞추겠습니다. 회신을 부탁드리는 것은 10장에 모았습니다.

1요청 요약

요청 1

회원 로그인은 samplepcb 가 맡습니다

SmartSMT 는 아이디·비밀번호를 받지 않습니다. samplepcb 가 로그인을 확인하고, 회원 아이디가 든 토큰을 붙여 SmartSMT 로 보냅니다.

요청 2

서버 간 호출도 같은 토큰으로

X-API-Key 대신 Authorization: Bearer 헤더에 토큰을 싣습니다. 양방향 모두 같습니다.

요청 3

나눠 갖는 것은 비밀 하나

두 서버가 같은 비밀 문자열을 설정에 넣어 둡니다. 로그인과 서버 호출이 모두 이 하나를 씁니다.

고정 키를 그대로 보내지 않는 이유

  • SmartSMT 는 지금 평문 HTTP 입니다. 헤더에 키를 그대로 실으면 요청마다 키가 드러나고, 한 번 드러난 키는 바꿀 때까지 계속 쓸 수 있습니다.
  • 토큰 방식에서는 비밀 자체가 전송되지 않습니다. 지나가는 것은 2분 뒤 못 쓰게 되는 토큰뿐입니다.
  • 구현은 표준 JWT 라이브러리로 만들기 한 줄, 검사 한 줄입니다(7장).

3토큰 규칙

로그인 인계와 서버 간 호출이 같은 규칙을 씁니다. 표준 JWT 이고, 서명 방식은 HS256(공유 비밀로 만드는 HMAC-SHA256) 하나로 고정합니다.

3.1 들어가는 칸

칸필수값
iss필수만든 쪽 식별자
aud필수받는 쪽과 쓰임. 3.2 의 표대로
iat필수만든 시각 (유닉스 초)
exp필수만료 시각. iat + 120 (2분)
sub로그인 토큰만samplepcb 회원 아이디
name로그인 토큰만회원 이름 (표시용)

3.2 쓰임 세 가지

쓰임issaud싣는 곳
회원 로그인 인계samplepcbsmartsmt-login주소의 token 파라미터
samplepcb → SmartSMT 서버 호출samplepcbsmartsmtAuthorization: Bearer
SmartSMT → samplepcb 서버 호출smartsmtsamplepcbAuthorization: Bearer

aud 가 쓰임을 가릅니다. 로그인 토큰을 서버 호출에 쓰거나 그 반대로 쓰면 aud 가 달라 거절됩니다. 그래서 받는 쪽은 자기 자리에 맞는 aud 만 받아야 합니다.

3.3 받는 쪽 검사

  1. 서명 방식이 HS256 인지 보고, 공유 비밀로 서명을 확인합니다. 틀리면 BAD_TOKEN. none 등 다른 방식은 받지 않습니다.
  2. iss 와 aud 가 이 자리에서 기대하는 값인지 봅니다. 아니면 WRONG_AUDIENCE
  3. exp 가 지나지 않았는지 봅니다. 시계 오차는 30초까지 봐줍니다. 지났으면 EXPIRED
  4. 로그인 토큰이면 sub 가 있는지 봅니다. 없으면 BAD_TOKEN

JWT 라이브러리가 1~3 을 한 번의 호출로 처리합니다.

3.4 오류 응답

서버 호출의 인증 실패는 401 이고, 본문은 지금 SmartSMT 개발 서버가 쓰는 모양과 같게 맞춥니다.

HTTP/1.1 401 Unauthorized
Content-Type: application/json

4회원 로그인 인계

회원의 브라우저만 두 사이트를 오갑니다. 로그인을 위해 두 서버가 서로를 부르지 않습니다.

  1. 회원이 SmartSMT 화면을 엽니다. SmartSMT 세션이 없으면 로그인 인계를 시작합니다.
  2. SmartSMT 가 브라우저를 samplepcb 의 인계 주소로 보냅니다. 돌아올 화면을 기억해야 하면 state 에 표시를 실어 보냅니다. samplepcb 가 그대로 돌려줍니다.
  3. 브라우저가 samplepcb 인계 주소를 엽니다.
  4. samplepcb 가 로그인 여부를 확인합니다. 로그인돼 있지 않으면 samplepcb 로그인 화면을 거칩니다.
  5. samplepcb 가 로그인 토큰을 만들어, 등록된 로그인 수신 주소로 브라우저를 보냅니다.
  6. 브라우저가 SmartSMT 의 로그인 수신 주소를 엽니다.
  7. SmartSMT 가 토큰을 검사하고(3.3, aud = smartsmt-login), sub 의 회원 아이디로 자체 세션을 만듭니다.
  8. SmartSMT 가 토큰이 없는 주소로 다시 이동시킵니다. 토큰이 주소창과 방문 기록에 남지 않게 하기 위해서입니다.
samplepcb 화면에서 SmartSMT 로 들어갈 때 samplepcb 의 메뉴는 인계 주소(③)로 바로 연결합니다. 회원은 이미 로그인돼 있으므로 ⑤ 부터 이어져 곧바로 SmartSMT 화면이 열립니다.

4.1 인계 주소 samplepcb 제공

GET {SAMPLEPCB}/spcb/sso/smartsmt?state={state}
이름필수뜻
state선택SmartSMT 가 정한 임의의 값. 200자 이하, 영문 · 숫자 · - · _ 만. samplepcb 는 뜻을 보지 않고 그대로 돌려줍니다. 돌아올 화면을 찾는 표시로 쓰거나, 내가 보낸 요청이 맞는지 대조하는 데 씁니다.

결과는 등록된 로그인 수신 주소로의 302 이동입니다.

{로그인 수신 주소}?token={로그인 토큰}&state={state}
  • 회원이 로그인하지 않으면 SmartSMT 로 돌아가지 않습니다. samplepcb 로그인 화면에 머뭅니다.
  • 로그인 수신 주소는 요청 파라미터로 받지 않습니다. samplepcb 는 미리 등록한 주소(환경별 1개)로만 보냅니다. 주소를 파라미터로 받으면 다른 사이트가 토큰을 받아 갈 수 있기 때문입니다.

4.2 로그인 토큰

{
  "iss": "samplepcb",
  "aud": "smartsmt-login",
  "sub": "hong123",          // samplepcb 회원 아이디
  "name": "홍길동",           // 회원 이름 (표시용)
  "iat": 1794538800,
  "exp": 1794538920
}
  • sub 가 회원을 가리키는 유일한 값입니다. 견적서의 owner_mb_id 에 글자 그대로 넣어 주십시오.
  • 처음 보는 sub 이면 SmartSMT 쪽 사용자 정보를 그때 만듭니다. 미리 회원 목록을 맞출 필요는 없습니다.
  • 넘기는 회원 정보는 아이디와 이름 두 가지입니다. 더 필요한 항목은 회신 항목으로 요청해 주십시오.

4.3 로그인 수신 주소 SmartSMT 제공

개발 단계의 주소는 http://1.255.226.33:8090/auth/samplepcb 로 등록해 두었습니다. 이 주소에 아래 처리를 만들어 주시면 됩니다. 고객 화면이 다른 주소에 있거나 다른 경로를 쓰시려면 알려 주십시오 — samplepcb 쪽 등록값을 바꿉니다. (이 주소는 고객이 쓰는 SmartSMT 화면과 같은 주소여야 합니다. 여기서 만든 세션 쿠키가 그 화면에 실려야 하기 때문입니다.)

처리 순서는 다음과 같습니다.

  1. token 을 검사합니다. 실패하면 세션을 만들지 않고 안내 화면을 보입니다.
  2. state 를 보냈다면, 돌아온 값이 보낸 값과 같은지 확인합니다.
  3. sub 로 SmartSMT 세션을 만듭니다.
  4. 토큰이 없는 주소로 다시 이동시킵니다.

4.4 SmartSMT 세션 SmartSMT 책임

  • 세션 쿠키는 HttpOnly · SameSite=Lax 로 둡니다. HTTPS 로 바꾼 뒤에는 Secure 도 붙입니다.
  • 수명은 짧게 둡니다. 권장: 사용이 없으면 2시간, 길어도 12시간. 끝나면 로그인 인계를 다시 시작합니다(회원이 samplepcb 에 로그인돼 있으면 화면에 드러나지 않습니다).
  • SmartSMT 의 로그아웃은 SmartSMT 세션만 끝냅니다.
  • SmartSMT 담당자(견적을 계산하는 직원)의 권한은 SmartSMT 가 직접 관리합니다. 로그인 토큰에는 회원 아이디와 이름만 있고 권한 정보는 없습니다.

4.5 하지 않을 것

  • SmartSMT 화면에서 samplepcb 아이디 · 비밀번호를 입력받지 않습니다.
  • samplepcb 의 쿠키를 읽거나 믿지 않습니다.
  • 회원 아이디를 주소 · 폼 · 헤더의 다른 값에서 받지 않습니다. 오직 검사를 통과한 토큰의 sub 에서만 받습니다.
  • 토큰을 로그 · 분석 도구에 남기지 않습니다.

5.1 견적서 보내는 법 SmartSMT → samplepcb

지금 만들어 두신 전송(「견적서 전송 양식」의 multipart)을 그대로 쓰시면 됩니다. 바꿀 것은 보낼 주소와 인증 헤더 두 가지입니다.

  1. 토큰을 만듭니다 — iss = smartsmt, aud = samplepcb, 수명 2분. 규칙은 3장, 코드는 7.1 의 make_token
  2. 견적서와 파일을 multipart 로 묶습니다. 파트 구성은 아래 표 — 지금 양식과 같습니다
  3. POST https://new.samplepcb.co.kr/api/smartsmt/quotes 로 보냅니다. 헤더는 Authorization: Bearer {토큰} 입니다.
  4. 응답이 200 이면 끝입니다. 아니면 본문의 reason 으로 원인을 봅니다. 5.2 의 표
파트 이름필수종류내용
envelope필수값 · application/json견적서 JSON
quote_id선택값 · text/plain견적 번호. 보내면 견적서의 header.quote_id 와 같아야 합니다
order_id선택값 · text/plain주문 번호. 보내면 견적서의 header.order_id 와 같아야 합니다
gerber_archive선택파일고객이 올린 제조 파일 묶음
bom선택파일BOM
cpl선택파일CPL
  • 견적서에 꼭 있어야 하는 칸은 kind("smartsmt.quote") · envelope_version · header.quote_id · header.order_id · header.made_at · quote 여섯 개입니다. 나머지 칸은 있는 그대로 받아 보관합니다.
  • 파일을 함께 보내면 견적서의 파일 목록(files 의 part · bytes · sha256)과 대조합니다. 크기나 해시가 다르면 받지 않습니다.
  • 같은 quote_id 를 다시 보내면 덮어쓰지 않고 200(duplicate: true)으로 답합니다. 실패해서 다시 보내는 것은 언제든 안전합니다.
  • 같은 order_id 로 새 quote_id 를 보내면 그 주문의 새 견적으로 쌓이고, 마지막에 받은 견적을 최신으로 봅니다.
# curl 로 보내 보기 — envelope 는 < (값으로), 파일은 @ (파일로)
curl -X POST "https://new.samplepcb.co.kr/api/smartsmt/quotes" \
  -H "Authorization: Bearer $TOKEN" \
  -F "envelope=<envelope.json;type=application/json" \
  -F "quote_id=Q-123456-123456-123abc" \
  -F "order_id=123456789abc" \
  -F "gerber_archive=@board.zip;type=application/octet-stream" \
  -F "bom=@bom.csv;type=application/octet-stream" \
  -F "cpl=@cpl.csv;type=application/octet-stream"

같은 모양의 명령을 samplepcb 개발 환경에서 실제로 돌려 확인했습니다(처음은 duplicate: false, 다시 보내면 duplicate: true).

502FILE_STORE_FAILEDsamplepcb 쪽 파일 저장 실패. 견적은 저장되지 않았습니다.그대로 다시 보내면 됨
503NOT_CONFIGUREDsamplepcb 쪽 공유 비밀이 설정되지 않음samplepcb 에 알려 주십시오
  • 견적서에 모르는 칸이나 모르는 코드 값이 있어도 받습니다. 견적서 양식이 바뀌어도 위의 여섯 칸만 있으면 거절하지 않습니다.
  • 파일은 gerber_archive · bom · cpl 세 파트만 받습니다. 파일 없이 견적서만 보내도 받습니다.

6공유 비밀 다루기

  • 32바이트 이상의 난수 문자열입니다. samplepcb 가 만들어 전달드립니다.
  • 개발용과 운영용을 다른 값으로 씁니다. 지금 전달하는 것은 개발용입니다.
  • 서버 설정(환경 변수 등)에만 둡니다. 소스 저장소 · 문서 · 화면 코드에 넣지 않습니다.
  • 브라우저로 내려가는 코드에서 쓰지 않습니다. 토큰을 만들고 검사하는 일은 서버에서만 합니다.
  • 새어 나간 것 같으면 바로 알려 주십시오. 새 값으로 양쪽 설정을 바꾸면 그때부터 옛 값으로 만든 토큰은 통하지 않습니다.
# 같은 형태의 값을 만드는 명령 (참고)
openssl rand -base64 48

이 비밀은 SmartSMT 연동에만 쓰는 값입니다. samplepcb 의 다른 인증에는 쓰이지 않습니다.

7예시와 검증 견본

7.1 Python 예시 (PyJWT 2.x)

참고용 예시입니다. 실행해 검증한 코드가 아니므로 SmartSMT 코드에 맞춰 써 주십시오.

import os, time
import jwt   # pip install pyjwt

SECRET = os.environ["SAMPLEPCB_SHARED_SECRET"]


def make_token() -> str:
    """samplepcb 를 부를 때 — 요청마다 새로 만든다."""
    now = int(time.time())
    claims = {"iss": "smartsmt", "aud": "samplepcb", "iat": now, "exp": now + 120}
    return jwt.encode(claims, SECRET, algorithm="HS256")


def check_token(token: str, audience: str) -> dict:
    """samplepcb 가 만든 토큰을 받을 때."""
    try:
        return jwt.decode(
            token, SECRET,
            algorithms=["HS256"],                    # 다른 방식은 받지 않는다
            issuer="samplepcb", audience=audience,
            leeway=30,
            options={"require": ["iss", "aud", "iat", "exp"]},
        )
    except jwt.ExpiredSignatureError:
        raise AuthError("EXPIRED")
    except (jwt.InvalidIssuerError, jwt.InvalidAudienceError):
        raise AuthError("WRONG_AUDIENCE")
    except jwt.InvalidTokenError:
        raise AuthError("BAD_TOKEN")


# 견적서 가져가기 호출을 받을 때
check_token(bearer_token, audience="smartsmt")

# 로그인 수신 주소에서
claims = check_token(token_from_query, audience="smartsmt-login")
if "sub" not in claims:
    raise AuthError("BAD_TOKEN")
mb_id, name = claims["sub"], claims.get("name", "")

9지금은 하지 않는 것

개발 단계라 단순하게 시작합니다. 아래는 나중에 붙여도 이 문서의 구조를 바꾸지 않습니다.

항목언제내용
HTTPS실제 고객 오픈 전 필수평문 HTTP 에서는 SmartSMT 세션 쿠키와 고객이 올린 파일이 그대로 보입니다. 토큰으로는 막을 수 없습니다. 전환할 때 공유 비밀도 새 값으로 바꿉니다.
로그인 토큰 1회용 처리HTTPS 전환 뒤 검토한 번 쓴 로그인 토큰을 2분 동안 기억해 다시 오면 거절합니다.
보내는 서버 IP 제한운영 주소 확정 뒤samplepcb 가 SmartSMT 서버의 IP 에서 온 호출만 받습니다.
견적서 본문 서명견적을 주문 · 결제로 잇기 전 검토금액이 중간에 바뀌지 않았음을 확인하는 장치입니다.
개발 기간에는 시험 계정과 시험 파일만 써 주십시오 HTTP 구간에서는 주고받는 내용이 보호되지 않습니다. 실제 고객의 계정이나 제조 파일은 HTTPS 전환 뒤에 다룹니다.

10할 일과 회신 항목

SmartSMT 에서 해 주실 일

  • 공유 비밀을 서버 설정에 넣기
  • 로그인 인계: 세션이 없을 때 인계 주소로 보내기, 로그인 수신 주소 구현 (4장)
  • 회원용 화면에 자체 로그인 입력이 있다면 제거
  • 견적서 가져가기 호출에서 X-API-Key 대신 토큰 검사 (3.3)
  • 견적서 전송에 토큰 붙이기, owner_mb_id 는 받은 sub 그대로
  • 7.3 의 견본으로 토큰 검사 코드 확인

samplepcb 에서 할 일

  • 개발용 공유 비밀을 만들어 전달
  • 인계 주소 · 견적서 수신 주소를 개발 서버(https://new.samplepcb.co.kr)에 배포
  • 로그인 수신 주소 등록 — http://1.255.226.33:8090/auth/samplepcb 로 등록해 둠 (바뀌면 다시 등록)
